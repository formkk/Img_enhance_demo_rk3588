- 开发机（`192.168.0.30`）与数据机（`192.168.0.147`）**不在同一 LAN**：开发机 ARP `192.168.0.147 = FAILED`、数据机 ARP `192.168.0.102 = FAILED`，**同一 IP `192.168.0.101` 在两机 ARP 中 MAC 不同** ⇒ **两套 192.168.0.x 隔离网**。

### 2.1 O124 — LSRW 的配对性判定更正

**事实**：`docs/design/dataset.md` §4.2 记 LSRW「⚠️ **无配对 ⇒ 不可作训练对**」（来源 = 2026-09-18 联网检索）；实测（R2RNet 发布版）为 `Training data/{Huawei,Nikon}/{high,low}` + `Eval/…`，**文件名逐条一一对应**（Huawei 2450 / Nikon 3150；Eval 30 + 20），**同对灰度相关 0.874 / 0.964、跨场景对照 −0.078**。

| 选项 | 内容 | 依据 / 代价 |
|---|---|---|
| **① （建议）** 按实测**直接改判** | §4.2 该行改为"**sRGB（Huawei 手机 + Nikon 相机）；训练 5600 对 / 评测 50 对；配对成立**"，并注明来源 = **R2RNet 发布版** | 数据在手、判定与事实相反；代价 = 若原始 LSRW 划分与 R2RNet 版不同，则该数字**只对 R2RNet 版成立** ⇒ 须在行内注明版本 |
| ② **先补目视抽样再改判** | 从 `Training data` 抽 5~10 对逐对目视（可用 `/mnt/hub` 直读，**零额外传输**），确认后再改 | 更严；代价 = 多一轮交互；收益 = 把"相关分析"升级为"目视 + 量化"双证 |

## 4. C 组：L1 论文口径基线（O132~O134）

> **本组三项建议一次裁定**——三者同属 L1 的"口径定义"，分开定极易互相矛盾（如：口径取部署 shape、却要求 SSIM 与论文可比）。

### 4.1 O132 — 口径选择

**事实/张力**：存在**三种不可混用**的口径——① **论文可比**（数据集原生分辨率 / 论文 resize 规则）⇒ 可与论文比，**不能**与部署比；② **部署 shape**（512×288 / 960×544）⇒ 与部署一致，**不能**与论文比；③ 板上 RKNN ⇒ **归 §11.2 ①b 对齐回归，不属 L1**。**已发生的实例**：**M0-4 的 HQ 权重横比用的是 `PT FP32 / 512×288`（属口径②）** ⇒ 直接拿它对比论文数字属**错误对比**。

| 选项 | 内容 | 依据 / 代价 |
|---|---|---|
| ① 只出**论文可比口径** | 用数据集原生分辨率 + 论文 resize 规则 | 回答"权重用对没 / 起点多高"；**不能**支撑"迁移到部署域"的任何推断 |
| ② 只出**部署 shape 口径** | 沿用 §3.1 G1 几何与 pad/crop | 与部署一致；**不能**与论文数字对照（**M0-4 现状即此**） |
| **③ （建议）两者都出** | 同一权重、两套口径各报一次 | **增量最大**：两者之差 = **该数据集与本项目部署域的域差量化**，正是 §4.2 反复强调却**至今只有定性描述**的"域差"的**第一个数字**；代价 = 成本近双份（但 PT FP32 在 RTX 3090 上很快，**实际成本主要是工具改造而非算力**） |
| ④ 只出①，把②留给后续 U4 | 分阶段 | 代价 = 域差仍无法量化，且 M0-4 的 512×288 口径仍会与 L1 数字混用 |

### 4.2 O133 — 对照臂集合

**事实**：**ZDE++** 官方权重 `Epoch99.pth` **仅 1 个**；**HQ** 上游权重共 **9 个**（`LOL_v1` / `LOL_v2_real` / `LOL_v2_synthetic` / `NTIRE` / `SID` / `SDSD_indoor` / `SDSD_outdoor` / `FiveK` / `SMID`，均在 `refs/pre-research/pretrain_model/`），**M0-4 曾全跑 9 个**。

| 选项 | 内容 | 依据 / 代价 |
|---|---|---|
| ①（建议）**维持 9 个全跑** + ZDE++ 官方 1 个 | 与 M0-4 口径**可直接对照**（同表可比较两次结果） | 成本极低（PT FP32 推理）；收益 = 与既有报告**同口径可比** |
| ② HQ 精简为 3~4 个（如 `LOL_v1` / `LOL_v2_real` / `NTIRE` / `SID`） | 去掉明显域不符者 | 代价 = **与 M0-4 报告不可直接对照**；且 `SID`/`SMID` 的"低分"本身是**域差的证据**，删掉反而丢失信息 |
| ③ 最小集 = 本网络官方权重 + `no-op` | 只回答"起点多高" | 满足 §5.4.4 下界要求；**但放弃"哪个上游最好"的选型信息** |

**硬约束**：无论选哪项，**`no-op` 必须在表内**（§5.4.4 判据 = 相对增益）。

### 4.3 O134 — 指标实现口径

**事实**：仓内两处 SSIM 实现**不一致**——`tools/hq_eval.py` 的 `ssim_gray` = **11×11 高斯窗灰度 SSIM**（标准形态）；预研 `batch_eval_lolv2.py` 的 `compute_metrics` = **单窗口全局简化版**（用整图均值/方差代局部窗）⇒ **与论文不可比**；**无参考指标（NIQE / BRISQUE）仓内无实现**；**ZDE++ 侧无 L1 harness**（组件齐备但未串联）。

| 子问题 | 选项 | 依据 / 代价 |
|---|---|---|
| **(a) PSNR 通道口径** | ① 全通道（RGB 三通道平均）；② 灰度（Y）；③ 两套都报 | 论文口径多按全通道；`hq_eval.py` 现用**全通道 PSNR + 灰度 SSIM** ⇒ 若要可比须**先确认论文实现** |
| **(b) SSIM 实现** | ① 统一到 `hq_eval.py` 的 11×11 高斯（**仓内一致化**）；**② （建议）改用与论文完全一致的实现**（须查到论文所用库与参数）；③ 两套都报并通过差值说明敏感度 | **这是"论文可比"的硬前提**——实现不一致时，两个数字**不可比**，O132 选①/③ 也失去意义 |
| **(c) 无参考指标** | ① 新实现 NIQE / BRISQUE（有第三方实现可用）；② 只用自算量（亮度 mean / 对比度 / 噪声 σ）；③ 不纳入 | §5.4.4 已规定无参考用于"无 GT 子集"；`Test_MEF`/`NPE`/`DICM`/`VV` 四个无参考集**已收在本地**，不做则闲置 |
| **(d) ZDE++ harness** | ①（建议）**新建 `tools/zde_eval.py`**（PT FP32，含 8-iter 应用）；② 扩展 `tools/hq_eval.py`（加 `--network {hq,zde}` + 多布局适配）；③ 复用预研脚本 | ③ **不建议**（ONNX+tile、简化 SSIM、预研资产）；①/② 之别只在工程口味；**两者都须同时解决 §1.3 的"三种布局"缺口** |

## 5. D 组：U4 设计（O135~O136）

> **前置（非本组可解）**：**O31「摆正」未关闭** ⇒ **即便本组裁定完成，U4 也不得开工**（`docs/design/dataset.md` §1.2：O31 关闭前采集的校准/评测集**作废重采**）。

### 5.1 O135 — U4 的 a1 / a2 / b1 / b2 划分比例与规模

**事实**：`dataset.md` §4.6 / §5.4.2 **结构已定**（U4a = a1 配对 + a2 无 GT；U4b = b1 + b2），§5.2.2 已给 **U4a = 26 / U4b = 18** 的**总量**（IMX415 6+6+8 场景 + Canon 20/10 对）；**§4.6 明文把"两段内的配对 / 无 GT 子集划分与规模比例"标 `[待裁定]`**。

**两条方向相反的约束（§5.4.3，不可套同一个数）**：
- **b2（无 GT、供盲评）** ⇒ 受**评审成本**上限约束（**O46：1 人 1 轮**）；
- **U4a（含 a1）** ⇒ 受**效应量**约束（路线间差异越小，所需样本越多）。

| 选项 | 内容 | 依据 / 代价 |
|---|---|---|
| ①（建议）**由两条约束分别反推、而非按比例切** | **b2** 先按"1 人 1 轮盲评可完成"定上限（经验上单轮可比对量有限）；**a1** 按"要能区分 E0~E2 的候选差异"定下限；余量归 a2 / b1 | 与 §5.4.3 的表述**同构**，是唯一不违反该条的切法；代价 = 需先明确"单轮盲评的上限"（**又是一个取值**，建议同一裁定内给出） |
| ② 按 **50% 配对 / 50% 无 GT** 平分 | 简单 | 代价 = **与 §5.4.3 冲突**（两个约束方向不同，平分等于默认二者同量级） |
| ③ 按**验收判定强度**倾斜（b1 大于 a1） | 因为 b1 是**最终数值结论的唯一来源** | 代价 = a1 的选型能力下降（选型是 E0~E2 的判据来源） |
| ④ 先给**临时值**跑通流程、M4 前再定 | 不阻塞开工 | 会引入"临时值顶替"的风险（§10.4 discipline：空值 = 未定稿，**禁止留默认值顶替**）⇒ **不建议** |

### 5.2 O136 — U4 配对子集的 GT 来源归属

**事实**：§4.5（O39 已裁定）→ **合成为先 + 实拍后补**，其中"实拍"= **固定 ISP 与曝光、改光源亮度**（**非**改曝光）；**④(c) 双光路不采用**；§5.4.3-3 要求 **GT 来源须与训练集可区分**；但 **U4 的 a1 / b1 具体取哪种未落值**。

| 选项 | 内容 | 依据 / 代价 |
|---|---|---|
| **① （建议）a1 用合成、b1 用光源调制实拍** | 天然满足 §5.4.3-3（**来源不同**）；且 b1 作为最终数值结论，用**真实物理 GT** 更可信 | 代价 = b1 需实拍（受 O31 阻塞、成本高）；且 §4.5 已定"合成为先"⇒ b1 排在后面 |
| ② a1 / b1 **都用光源调制实拍** | 与部署域最接近 | 代价 = 全部绑定在实拍上 ⇒ **完全受 O31 与现场条件阻塞**，无合成兜底 |
| ③ a1 / b1 **都用合成** | 成本最低、不受 O31 阻塞 | ⚠️ **与 §5.4.3-3 冲突**：若 U3 主训 GT 也用合成 ⇒ **验证无独立性**，结论不能证明迁移；**若选此项，必须同步调整 U3 的 GT 来源**（连带裁定） |
| ④ a1 用合成 + b1 **两种都做** | b1 同时出合成 GT 与实拍 GT 两版 | 最严谨（可量化"合成 GT 是否可信"）；代价 = b1 规模翻倍，且 b1 是"只用一次"的验收集 |

## 6. 依赖关系与建议裁定顺序

```
第 1 批（U3 数据源；O124 为硬前置）
  O124 ──┬─> O125
         └─> O126          （可与 O125 合并裁定）
  O127（独立）

第 2 批（L1 口径；三项须一次裁完）
  O132 / O133 / O134

第 3 批（数据卫生；可并行、互不阻塞）
  O128 / O129

第 4 批（U4 设计；裁完仍受 O31 阻塞）
  O135 / O136

第 5 批（优先级最低）
  O130 / O131
```

**理由**
- **O124 必须最先**：其判定直接决定 O125/O126 是否成立；
- **O132~O134 必须同批**：单独裁任一项都可能与另两项矛盾（如"要论文可比"却保留简化 SSIM）；
- **O128 / O129 可并行**：纯数据卫生/运维，与口径无关，且 O129 的"按需解压子集"能直接服务 L1 与 U4；
- **O135 / O136 排在 O132~O134 之后**：U4 的判据口径（尤其"相对增益"与 GT 独立性）已由 L1 一组确定；
- **O130 / O131 最后**：前者取决于 U3 数据是否已足（O125/O126 的裁定结果），后者是归档定位。
