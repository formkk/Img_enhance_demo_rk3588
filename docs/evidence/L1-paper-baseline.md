## 1. 口径（O132 / O133 / O134 的执行落值）

| 项 | 取值 |
|---|---|
| **分辨率口径（O132）** | ① **论文可比** = 数据集**原生分辨率** + 官方 pad/4（`reflect`）② **部署 shape** = 等比缩放到内容 **960×540** + 上下各 **2 行零 pad** → **960×544** → 推理 → 裁回 **960×540**；GT 同步缩放到 960×540 |
| **对照臂（O133）** | **9 个上游权重**（`LOL_v1` / `LOL_v2_real` / `LOL_v2_synthetic` / `NTIRE` / `SID` / `SDSD_indoor` / `SDSD_outdoor` / `FiveK` / `SMID`）+ **`no-op`**（恒等，必列） |
| **指标（O134a/b）** | **PSNR = 全通道（RGB）**；**SSIM = 逐通道（R/G/B）各算再平均**；两者**直接调用官方 `Enhancement/utils.py`** ⇒ **位一致** |
| **GT_mean（新增口径项）** | **开 / 关两列**（复刻官方 `test_from_dataset.py --GT_mean` 语义，含其 `COLOR_BGR2GRAY` 通道序**原样**） |
| **无参考指标（O134c）** | **未纳入本轮**（NIQE/BRISQUE 实现未落盘；用于 a2/b2 无 GT 子集） |

### 1.1 ⭐ O134 硬前提已解除：论文所用库与参数**已查证**

官方 `Enhancement/test_from_dataset.py` **不用** basicsr 的指标，而用 **`Enhancement/utils.py`**：

| 项 | 官方实现（原文） |
|---|---|
| `PSNR` | `10·log10(1/MSE)`，**[0,1] 域、全通道（HWC 3 通道）**、`border=0` |
| `calculate_ssim` | `img_as_ubyte(...)`（8-bit）→ **逐通道（R/G/B）各算 `ssim()` 再 `np.mean`** |
| `ssim` | 窗 = **`cv2.getGaussianKernel(11, 1.5)` 外积**；`C1=(0.01·255)²`、`C2=(0.03·255)²`；`cv2.filter2D(..., -1, window)[5:-5,5:-5]`（**valid**） |
| `--GT_mean` | `restored ×= mean(gray(GT)) / mean(gray(restored))` 后 `clip(0,1)`（**gray 用 `COLOR_BGR2GRAY` 施加于 RGB 数组 —— 官方原样保留**） |

⇒ **O134a（PSNR 全通道）与官方一致 ✓**；**O134b 的「论文实现」查明** = 上表（**不是**仓内 `hq_eval.py` 的**灰度**版，也**不是** `basicsr` 的 Y 通道版）⇒ **可落值**。

### 1.2 ⭐ `GT_mean` 选用策略（**v3.86 追加 130 裁定**）

**裁定（用户 2026-09-24 确认）** —— **主判据口径 = `GT_mean` 关**；**`GT_mean` 开 = 副口径，仅用于「与公开文献表对照」**（KinD / LLFlow / 近年扩散类用 ON），且**必须标注 `oracle`**（用 GT 统计量、**部署不可得**）。**报告两列并出（可追溯），但判据不得读 ON 列。**

**依据（本档实测，论文可比口径）**：

**(a) 增益与臂的失配程度正相关**（`ON − OFF` 的 PSNR 增益，dB）：

| 臂 | LOL_V1 | LOL_V2_Real | LOL_V2_Syn |
|---|---|---|---|
| **no-op（恒等）** | **+11.02** | **+9.29** | **+4.63** |
| LOL_v2_synthetic | **+10.15** | +7.41 | +3.37 |
| SMID | +5.30 | +2.12 | +2.99 |
| LOL_v2_real | +4.00 | +4.91 | +2.33 |
| SDSD_outdoor / indoor | +4.00 / +3.85 | +3.61 / +3.91 | +3.26 / +2.98 |
| NTIRE | +3.78 | +3.14 | +2.73 |
| SID | +2.65 | **+1.34** | +3.22 |
| **LOL_v1（同域最强）** | **+2.03** | **+1.74** | +2.79 |

⇒ **越差的臂增益越大**（no-op **+11.02** vs 同域最强 **+1.74**）⇒ GT_mean 起「**全局亮度均衡器**」作用，**压缩臂间排序、掩盖差异**。

**(b) ⚠️ 排名反转（决定性）**：

| 验证集 | `GT_mean` 关 | `GT_mean` 开 |
|---|---|---|
| **LOL_V1** | … > SID(14.26) > SMID(11.04) ≈ FiveK(11.04) > LOL_v2_syn(10.89) > **no-op(7.77，垫底)** | … > **no-op(18.79) > SID(16.91) > SMID(16.34) > FiveK(15.09)** ⚠️ |
| **LOL_V2_Real** | … > SID(17.28) > SMID(13.72) > FiveK(13.32) > LOL_v2_syn(13.20) > **no-op(9.72，垫底)** | … > **no-op(19.01) > SID(18.62) > SMID(15.84) > FiveK(15.36)** ⚠️ |

⇒ **`GT_mean` 开时「什么都不做」反而超过 SID / SMID / FiveK 三个真模型** ⇒ **破坏「恒等臂必须垫底」这一健全性性质** ⇒ **不可用于选型 / 优劣判断**。

**(c) 机理** —— GT_mean 把输出整体缩放到与 GT 同均值 ⇒ **正好抹掉「全局亮度不匹配」这一误差分量**；而跨域 / 未适配的臂（`no-op`、`LOL_v2_synthetic`）的误差恰恰**主要是全局亮度** ⇒ 增益最大；同域臂本身亮度已接近 GT ⇒ 增益最小。

**效力边界（硬约束）** —— ① **判据 / 选型 / 微调前后 Δ 一律读 OFF 列**；② ON 列只出现在「与文献对照」小节并标注 `oracle`；③ 若日后确需「亮度已对齐」的指标，须改用**部署可得**的对齐方式（如固定 AE 目标亮度），**不得**用 GT 统计量；④ **两列不得混在同一张判据表里比**（与 O132 的「两套口径不得混表」同源纪律）；⑤ **微调前后对比若误用 ON 列**，会把「全局亮度改善」与「结构 / 颜色改善」混为一谈，且其 oracle 增益足以**掩盖真实退化**（no-op 的 +11.02 dB 即极端例证）。

| `LOL_V2/Real_captured/Train/Low` | **689** | 1..689 |

| 交集 | 计数 |
|---|---|
| `LOL_V1.train` ∩ `LOL_V2_Real.test` | **86**（占其 test 的 **86%**） |
| `LOL_V1.train` ∩ `LOL_V2_Real.train` | **399** |
| `LOL_V1.test` ∩ `LOL_V2_Real.train` | **12** |
| `LOL_V1.test` ∩ `LOL_V2_Real.test` | **3**（748 / 778 / 780） |

⇒ **两集系同一批场景的重拍**（编号空间 1..789 **全面**重叠）。**⭐ 关键推论（v3.86 追加 132 补正）** —— **`LOLv1.train` 独有场景 = 0**（`LOL_V1.train ⊆ LOL_V2_Real.train ∪ LOL_V2_Real.test` 实测为 **True**；其 485 张 = **399** 与 v2R.train 同 id + **86** 与 v2R.**test** 同 id）⇒ **合并两训练集后「干净可用训练池」仍 = 689**（**LOLv1 新增 0**），且**那 86 张直接与 v2R test 重叠（泄漏）** ⇒ **不得合并**。**另**：**`LOL_V1/test_low`（eval15）的 15 张全部**落在 v2R 场景空间内（**12** 在 v2R.train、**3** 在 v2R.test）⇒ **该 test 集整体不可作验证集**（**不只是 12/15**）。`LOL_V2_Real.train ∩ test = 0` ⇒ **官方划分本身干净**。

**⇒ 受影响的结果（作废 / 标注）**：

| 数字 | 状态 |
|---|---|
| **`LOL_v1` 臂 @ LOL_V2_Real = 28.983 / 0.8821** | **❌ 作废**（**86/100 场景在 LOLv1 训练集内 ⇒ 严重泄漏**）⇒ **不得用作跨域泛化证据**，**亦不得作为「微调起点选型」的理由** |
| `LOL_v2_real` 臂 @ LOL_V1 = 21.845 / 0.8246 | **⚠️ 轻度污染**（eval15 中 **12/15** 场景在 LOLv2-real 训练集内）⇒ 报告须标注；**真实干净值应更低** |

**对数据构建的连带约束（Phase B 用）** —— ① **跨数据集合并必须按场景去重**（否则 399 个场景被加权 2 倍且造成泄漏）；② **`LOL_V1/test_low` 不可作验证集**（其 12/15 场景在 LOLv2-real 训练集内）；③ **`LOL_V1` 与 `LOL_V2-real` 不得一个做训练、另一个做验证**（场景级重叠）。

### 3.2 ⭐ 干净子集上的**正面对比**：`LOL_v2_real` 反超（**v3.86 追加 141 新增**）

**动机** —— §3.1 证明 `LOL_v1` 与 `LOL_v2_real` 在 LOL 系**任何**集合上都难以公平比较。但 **`LOL_V2_Real.test` 的 100 张里有 14 张是「两个权重都未见过」的**（100 − 86）⇒ 这 14 张构成**目前唯一可用的干净正面对比子集**。

| 子集 | **`LOL_v1`** | **`LOL_v2_real`** | Δ（v1 − v2） |
|---|---|---|---|
| 全部 100 | 23.731 / 0.8361 | 22.318 / 0.8429 | **+1.413 dB** ← 假象 |
| **干净 14 张** | **20.166 / 0.7724** | **21.541 / 0.8142** | **−1.376 dB · SSIM −0.042** ← **v2 胜** |
| `LOL_V1` 见过 86 张 | 24.311 / 0.8465 | 22.444 / 0.8475 | **+1.867 dB** ← 纯泄漏 |

（口径 = **部署 shape 960×544** · `GT_mean` **关** · 官方 PSNR/SSIM · **同一批帧**；逐图数据 = `docs/evidence/reports/L1/pt_metrics.json`〔`LOL_v2_real`〕与 `pt_lolv1_metrics.json`〔`LOL_v1`〕）

**读数** —— **`LOL_v1` 在全部 100 张上「领先」的 +1.413 dB 全部来自泄漏**；去掉泄漏后 **`LOL_v2_real` 在 PSNR 与 SSIM 上同时反超**。**逐张为 7:7 平分**（单张差异可达 ±几 dB）⇒ n=14 样本小、均值差**方向可信度中等**，但**两指标同向**使其更可信。

**⚠️ 板端选型依据本身不干净（追加 141 登记）** —— 板端 HQ 三档**全部由 `LOL_v1.pth` 转出**（`export_hq_{512x288,768x432,960x544}_lolv1.json`，sha256 `9b4810dc…`）。其选型依据是 §4.1 的**上游权重横比**：**LOLv2 `Real_captured/Test` 前 20 对 / PT FP32 / 512×288**，`LOL_v1` **23.98** vs `LOL_v2_real` **23.79** ⇒ **只差 0.19 dB，且那 20 对 86% 被 `LOL_v1` 见过**（§3.1）⇒ **该选型基础被污染**，且与本节的干净口径结果**方向相反**。

**另一条同向先验** —— `LOL_V1.train ⊆ LOL_V2_Real.train ∪ LOL_V2_Real.test`（§3.1）⇒ **`LOL_v2_real` 的训练场景集是 `LOL_v1` 的超集**（含其 **399** 个共享场景 + **290** 个新场景），**同源同域、数据更多** ⇒ 先验上亦更强。

**⚠️ 效力边界（硬约束）** —— 本节**只登记事实、不作裁定**；**不得据此直接换板端权重**：① n=14 样本小；② **LOL 域 ≠ 部署域**（O139「成像实现域不可转换」）⇒ 公开集排序**推不出**暗箱 / IMX415 排序；③ **换权重属 §15 O11 范畴**（权重变更 ⇒ M0-2/3/4/5/8 结论作废并全量重跑）。**正解 = 在真实暗箱帧上做 A/B 目视**（项目既定裁定方式）。

## 5. 结论（供后续选用，**不构成裁定**）

1. **同域基线已确立**（三臂全中官方数字）：`LOL_v1`→LOL_V1 **25.16**；`LOL_v2_real`→LOL_V2_Real **22.80**；`LOL_v2_synthetic`→LOL_V2_Syn **25.67**（`GT_mean` 关）。
2. **跨域落差显著**（`GT_mean` 关）：如 `LOL_v2_synthetic` 臂从同域 **25.67** 掉到 LOL_V1 **10.89**（**−14.8 dB**）、LOL_V2_Real **13.20**（−12.5 dB）；`LOL_v1` 臂在 LOL_V2_Syn 仅 **16.19**（−9.0 dB）⇒ **域差是主导因素**，与「9 臂横比」的设计意图一致。
3. **`no-op` 基线**：LOL_V1 **7.77** / LOL_V2_Real **9.72** / LOL_V2_Syn **11.22** ⇒ 各臂相对增益可由此算（判据形式 = 相对增益，§5.4.4）。
4. **部署 shape 口径的系统性代价**：论文口径 → 部署口径普遍 **−0.3 ~ −5.7 dB**（如 `LOL_v1`@LOL_V2_Real 28.98 → 23.27，**−5.71 dB**；`LOL_v1`@LOL_V1 25.16 → 22.01，−3.15 dB）⇒ **这是「该数据集与部署域的域差」的第一个数字**（O132 的目的）。**⚠️ 归因随行**：LOLv1/LOLv2 原生为 **600×400**，部署口径需**上采样**到 960×540 ⇒ 该差含**重采样损失**，非纯域差。
5. ~~**`LOL_v1` 臂在 LOL_V2_Real 上反而最高（28.98 > 同域臂 22.80）** ⇒ **疑似场景重叠**~~ ⇒ **已查明 = 场景泄漏（见 §3.1）** ⇒ **该数字 ❌ 作废**（86/100 场景在 LOLv1 训练集内），**不是跨域泛化能力**。
6. **微调起点的候选**（供 Phase B/C 用，非裁定；**已按 §3.1 修正**）—— ~~`LOL_v1` 在真实拍摄集上交叉表现最好~~ **该依据已作废（泄漏）**。~~现有数据无法分出 `LOL_v1` 与 `LOL_v2_real` 的高下~~ ⇒ **（v3.86 追加 141 更新）现已在唯一干净子集上分出高下**：**干净 14 张上 `LOL_v2_real` 反超 1.376 dB 且 SSIM 亦高 0.042**（见 §3.2）。**⚠️ 但该结论不得直接用于板端选型** —— **LOL 域 ≠ 部署域**（O139）⇒ **须在真实暗箱帧上 A/B 目视**。**`LOL_v2_synthetic` 不宜起训**（合成域权重，真实集上仅 10.89–13.20）。**具体选型须另行裁定**。
