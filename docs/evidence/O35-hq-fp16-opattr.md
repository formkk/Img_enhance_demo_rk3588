## 1. 目的

§11.2 M0-①b 要求"板上 RKNN FP16 输出 vs PyTorch"张量差 ≤1e-3。`docs/evidence/M0-4-hq-r9-gate.md` §7.3 实测三档 **4.604e-3 / 6.465e-3 / 8.929e-3**（对纯 FP16 舍入底 **9.4 / 13.2 / 18.3×**）**全不过**。§8.3 收敛出三条未排除方向：① 算子近似实现；② 中间累加精度；③ 编译期融合/重排。本文用**微模型逐算子归因**把这三条分开。

## 2. 方法

**核心设计**：把 HQ 图里的**单类算子**做成微型 ONNX，但**输入不是随机数**——而是从正式模型（PyTorch FP32）**真实抓取的中间张量**。这样每个微模型测算的就是"该算子在真实数据分布下的板上偏差"。

| 项 | 设置 |
|---|---|
| 工具 | **`tools/opattr.py`**（新增；`dump` / `export` / `compare` 三段），报告原档 `docs/evidence/reports/M0-4/opattr2/` |
| 抓取方式 | `dump`：真模块用 `register_forward_hook`；`F.normalize` 用**函数替换**（IG_MSA 对 q/k 的调用点）；注意力核心按 `IG_MSA.forward` 算式在 float64 重建（输入 = 真实 `k_n @ q_n^T * rescale`，右操作数 = 真实 `v * illu_attn`） |
| 微模型导出 | `torch.onnx.export`（opset 12，固定输入）→ `onnxsim`；每档与 PT 参考**自检对齐**（见 §4 表 `ONNX↔PT`） |
| 编译配置 | 与正式模型**逐项一致**：`target_platform='rk3588'`、`do_quantization=False`（FP16）、`quant_img_RGB2BGR=False` |
| 唯一刻意差异 | `mean/std` —— `convert_models.py` 固定 3 值，只适用于 3 通道输入；本工具按 RKNN 读取的 `dims[1]` 生成**恒等归一化**（mean=0 / std=1）。**恒等归一化数值上是 no-op**，不改变被测算子的输入值域（规则 `20-contracts.md` §1 未新增任何 config 键） |
| 板上执行 | `tools/rknn_c_probe`（C API），`core_mask=0`（AUTO）、`float`、`nosram`、`noperf`，3 runs，输出落盘后回传 PC 比对 |
| 比对口径 | 参考 = **PT FP32**（同一真实输入）；对照 = **纯 FP16 舍入**（把 PT 输出投到 float16 再回来）；**超出倍率 = 板上偏差 / 纯舍入偏差** |

**测量条件随行**：板 **LubanCat-5 V2** / 板端 **librknnrt 2.3.2**（`2.3.2 (429f97ae6b@2025-04-09T09:09:27)`，进程实测）/ 驱动 **0.9.8** / PC **rknn-toolkit2 2.3.2**（env `rknn232`，`PYTHONNOUSERSITE=1`）/ opset **12** / 权重 **`LOL_v1.pth`** sha256 `9b4810dc…32cd1` / 架构 `RetinexFormer_arch.py` sha256 `1567c89d…87631` / 输入 = `docs/evidence/reports/M0-4/gate_input_512x288.png`（`h=288,w=512`）/ 归一化 `mean=0,std=255`。

**为什么微模型是可信的**：编译日志逐条核对，每个微模型都**被 RKNN 映射到与正式图相同的层类型**（见 §4"RKNN 层类型"列）。`norm40` → `replace_torch_layernorm` + `exNorm`；`l2norm_*` → `2lpnorm2`（exNorm）；`convg` → `ConvExGelu`；`attn_softmax` → `exSoftmax13`；`conv3x3` → `Conv`。

## 3. 被测算子在正式图中的规模（512×288 编译日志逐层表）

| RKNN 层类型 | 层数 | 来源 | 形状特征 |
|---|---|---|---|
| `exNorm` | **24** | 16× `2lpnorm2`（`F.normalize` 的 L2 归约）+ **8× LayerNorm**（`nn.LayerNorm(40)`） | L2 形态 `(1,N,1,40)`，N = **147456 / 36864 / 9216**；LayerNorm 形态 `(1,40,288,512)` |
| `Conv` | 52 | 卷积/线性 | — |
| `ConvExGelu` | **24** | `Conv` + `Erf`（GELU）融合 | — |
| `exMatMul` | 68 | 注意力 `k@q^T`、`attn@v`、`to_q/k/v`、`proj` | 归约长度 40 |
| `exSoftmax13` | 8 | 注意力 softmax | 归约长度 40 |
| `ConvAdd` / `Add` / `Mul` / `Reshape` / `Transpose` / `Split` / `Concat` | 9 / 69 / 9 / 51 / 30 / 16 / 3 | 布局与逐元素 | — |

**关键结构事实**：`exNorm` 是**同一个层类型**承载两种语义——**长归约的 L2 范数**（N 最大 147456）与**短归约的通道 LayerNorm**（C=40）。这使"归约长度"成为一个可独立操纵的变量。

### 4.1 三条待查方向的判定

| §8.3 待查方向 | 判定 | 依据 |
|---|---|---|
| ① **算子近似实现**（GELU / Softmax） | **部分成立，但不是主因** | `attn_softmax`（exSoftmax13）超出仅 **2.6× / 2.3×**，接近纯舍入底；`convg`（ConvExGelu）**max 超出 3.2×、mean 超出 19.4×** ⇒ GELU 是**次级**来源（均值层面倍率最大） |
| ② **中间累加精度**（长归约） | **不成立** | `l2norm` 的归约长度从 9216 → 147456（**16×**）时，**绝对**误差几乎不变（1.65e-4 → 1.32e-4，甚至下降），远低于 1e-3；超出倍率虽随 N 上升（3.2 → 8.7×），但**基数极小**（1e-4 量级）⇒ 长归约**不是**超阈来源 |
| ③ **编译期融合/重排改变数值路径** | **不能排除，但已不必要** | 见下条：主因已被单个算子的**直接测量**定位，无需诉诸"融合路径"这一不可直接观测的解释 |

### 4.2 主因：`exNorm` 的 **LayerNorm 形态**

**`norm40` 的超出倍率 = 9.4×，与正式模型 @512×288 的整链倍率（4.604e-3 / 4.882e-4 = 9.4×）完全相同**；其**单算子**板上偏差 **1.815e-2** 甚至**大于**正式模型的整链输出偏差（4.604e-3）——说明该算子是全链误差的主导贡献者，下游（注意力/卷积）只做了衰减与混合。

### 4.3 已排除：`eps` / 方差约定不符（**受控对照**）

对同一真实输入，用**真实权重与偏置**手工复现 LayerNorm 并扫 `eps` 与方差约定（偏置/无偏），与板上输出比对：

| 假设的约定 | 板上 vs 该假设 max | 参考 vs 该假设 max |
|---|---|---|
| **eps=1e-5、有偏方差（= `nn.LayerNorm(40)` 默认）** | **1.815e-2** ← 最接近 | **9.54e-7**（自检通过） |
| eps=1e-6 | 3.903e-2 | 3.579e-2 |
| eps=1e-8 / 1e-12 | 4.283e-2 / 4.287e-2 | 3.981e-2 / 3.985e-2 |
| eps=1e-4 | 2.933e-1 | 2.952e-1 |
| 无偏方差（÷(N−1)） | 6.957e-2 | — |

⇒ 板上输出**最接近正确的约定**（eps=1e-5、有偏方差），**不是**换用了别的 eps 或方差口径 ⇒ 该偏差是 `exNorm` 计算路径的**数值精度损失**，而非语义/约定不符。

### 4.4 全链误差的分布形态（说明"不是个别离群点"）

| 档 | n | max | p99.99 | p99.9 | p99 | mean | **>1e-3 占比** |
|---|---|---|---|---|---|---|---|
| 512×288 | 442,368 | 4.604e-3 | 3.187e-3 | 1.951e-3 | 1.381e-3 | 3.268e-4 | **4.24%** |
| 768×432 | 995,328 | 6.465e-3 | 4.628e-3 | 2.038e-3 | 1.132e-3 | 2.464e-4 | **1.55%** |
| 960×544 | 1,566,720 | 8.929e-3 | 6.960e-3 | 3.898e-3 | 1.348e-3 | 3.013e-4 | **3.22%** |

⇒ **p99 已超 1e-3**，即该阈被 **1.5%~4.2% 的输出元素**突破 ⇒ 属**面状**偏差，不是"个别离群点"。三档的 `mean` 基本持平（2.5~3.3e-4）、`p99` 基本持平（1.1~1.4e-3），只有**尾部**随分辨率增长。

## 6. 口径与限制（随报告给出）

1. **单算子误差 ≠ 整链贡献**：本文量的是"该算子在真实输入下的**直接**偏差"，未做误差传播建模。主因判定依据是 **9.4× 的倍率与整链 9.4× 完全一致** + **单算子绝对偏差大于整链**，而非传播计算。
2. **`norm40` 只测了第 1 个 LayerNorm**（`encoder_layers.0.0/blocks.0.1/norm`）。8 个 LayerNorm 的输入分布不同，**其余 7 个未逐个测量**。
3. **`attn_av` 未映射为 `exMatMul`**：该微模型的右操作数是**常量入图**（真实 `v*illu` 作为 initializer），RKNN 把它编译成了卷积类而非 `exMatMul` ⇒ **`exMatMul`（68 层）的板上精度本轮未被直接测量**，其 1.8× 的结果**不得**当作 `exMatMul` 的证据。
4. **三档分辨率的尾部增长未定位**：`mean` / `p99` 三档持平，只有 `max` / `p99.9` 随分辨率增长。**本文不给出解释**（规则 `10-evidence.md` §2：现象 + 待查）。
5. **`l2norm` 探针是"同一张真实 q 张量的前缀截断"**（N 取该模型内自然出现的 9216 / 36864 / 147456），不是三个独立场景的张量；`l2norm_n147456` 为未截断的真实张量。
6. **板上无输出量化的影响**：`want_float=1` 只影响 wall 耗时（约 +20 ms），不影响数值。
7. **`exMatMul` 的直接测量受"合成退化输入形状"伪影污染（v3.56 实测）**：为生成真正的 `exMatMul`，我构造了一个**双输入 `[1,40,40] × [1,40,N]` 的 MatMul**（input0 = 真实 softmax 输出、input1 = 真实 v*illu）。**N≤36864 下干净**（corr=1.0000、超出纯 FP16 舍入 **1.8×~2.6×**）；**但在 N=147456（= 512×288 的 h*w）下损坏**（`mm_n147456`：corr 0.018、excess 3306×）。**对照实验证明损坏与算子无关**——同一 `v` 上做**纯 passthrough `y=2x`**（连一个乘加都没有）在 N=147456 同样损坏（`scale2`：corr 0.14、excess 3489×），且编译日志出现 `REGTASK: The bit width of field value exceeds the limit, target: v2, ..., limit: 0x1fff` ⇒ **根因 = `[1,40,147456]` 这类"窄高"合成输入使 NPU 存储描述符字段（13-bit）溢出**，导致**输入张量的布局/内存转换**即已损坏，发生在任何算子之前。
   - **推论**：**微模型不是 `exMatMul` 的忠实载体**——HQ 真实的 `exMatMul` 操作数是**注意力 reshape 后的 `[b,heads,n,hw]`-型张量**（n=40、hw=147456 分开的 5D 内部排布），而非这种 `[1,40,hw]` 裸特征；用"窄高裸输入"去喂 exMatMul 会先触发布局伪影。**因此 `exMatMul` 的直接精度在本微模型框架下不可靠**，改由 M2-2 的 HQ 定版集成复测（对真实 reshape 路径）观察。
   - `rknn_c_probe.c` 增**第 12 参 = 第二 float32 输入**（`opattr.py` 增 `dump_probe2` / `matmul_mm_wrapper` / `build_rknn` 双输入 mean-std）。

## 7. 结论（本轮）

1. **HQ 板上 FP16 误差超 ①b 阈的主因是 `exNorm` 的 LayerNorm 形态**（`nn.LayerNorm(40)`）：单算子超出纯 FP16 舍入 **9.4×**（max）/ 5.8×（mean），与整链 @512×288 的 **9.4×** 完全一致，且单算子绝对偏差（1.815e-2）**大于**整链输出偏差（4.604e-3）。
2. **次级来源是 `ConvExGelu`**（GELU 融合进卷积）：max 超出 3.2×、**mean 超出 19.4×**（全部探针中均值倍率最大）。
3. **普通 `Conv`（1.7×）、`exSoftmax13`（2.6×）接近纯舍入底，不是超阈来源。**
4. **§8.3 的"中间累加精度（长归约）"方向不成立**：`l2norm` 的归约长度放大 16×（9216 → 147456）后**绝对**误差基本不变且远低于 1e-3。
5. **不是 `eps` / 方差约定不符**（受控对照：板上最接近正确约定 eps=1e-5、有偏方差）。
6. **该阈被 1.5%~4.2% 的输出元素突破**（p99 已超 1e-3）⇒ 属面状偏差。
7. **仍未定位**：`exMatMul`（68 层）的直接精度；三档 `max` / `p99.9` 随分辨率增长的机制（§6-4）。
   **（v3.56 补充）** `exMatMul` 的**测量**已尝试并**失败于微模型载体**（§6-7）：在 N≤36864 上双输入真实 `exMatMul` 干净（**1.8×~2.6×**，corr=1.0000），但在 N=147456 上被"窄高合成输入"的 NPU 描述符位限伪影污染（**纯 passthrough 对照同样损坏** ⇒ 与算子无关）。**⇒ 该残留从"未测"改为"已尝试、载体不可靠"**，改由 **M2-2 的 HQ 定版集成复测**（对真实 reshape 路径）观察。**§6-4 的分辨率尾部增长仍未定位**，保持不变。

**⇒ O35 的"根因定位"义务已完成**（超阈来源 = `exNorm`(LayerNorm) 为主 + `ConvExGelu` 为辅）。**①b 阈值口径的处置（是否按同模型实测重定、是否改以图像域为主、是否接受某档并走 §6.2 阶梯、是否改网络结构）仍待 §15 裁定**——本文不预设结论，也不放宽任何验收上限（规则 `40-gate.md` §5）。

§7 第 7 条列出的"①b 阈值口径处置仍待裁定"**已于 v3.55 就地裁定**（用户 2026-09-19 选择方案 ①：**按模型族重定 FP16 阈、HQ 单独一档**）。裁定正文 = 主基准 §15 的 **O35** 行 + §11.2 M0-①b 行；本档只记**与该裁定直接相关的口径**，不复制定值以外的取值（规则 `00-ssot.md` §3.1）。

| 项 | 内容 |
|---|---|
| 裁定值 | **①b 的 FP16 档按「模型族 × 精度档」细分**：ZDE++ 族不变；**新增 HQ（Retinexformer）族**。U8 场档与 INT8 档不变 |
| 标定方法 | 延续 O27 的"以本工程实测为基线、留约 1.4~1.7× 余量"，只把"精度档"细化为"模型族 × 精度档" |
| 余量核对（以最差档 960×544 为基准） | 张量：1.5e-2 / 8.929e-3 = **1.68×**；图像域：64 dB ↔ RMSE **0.161 LSB**、实测 67.35 dB ↔ **0.109 LSB** ⇒ **1.48×** ⇒ 两条判据**均落在 1.4~1.7× 带内** |
| 三档按新档判定 | **全部过档**（4.604e-3 / 67.35 dB、6.465e-3 / 69.87 dB、8.929e-3 / 68.23 dB） |
| 效力边界 | **仅新增"HQ 模型族"这一 FP16 子档**；**不放宽 §13 任何验收项**（§13「实时画质」仍走盲评 + FPS/延迟判据）、**不改变 §9.3 的 R9 判据**、**不改变 ①a**、**不解决 O37**；**阈值的下一次调整仍须走 §15** |

| 未采纳的选项 | **④（改网络结构/裁剪注意力）不采纳**——按新档后 HQ 已过 ①b，改网络无必要；将来若要提精度另立新 O 项。**③（接受某档并据 §6.2/§9.3 阶梯处置）不属 O35**，属 **O37**（仍开放） |
