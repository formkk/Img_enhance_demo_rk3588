## 3. ⭐ 主因初判：**本帧最大的画质问题是「色偏被放大」，不是噪声**

1. **原图本身已严重偏色**：ISP 直出 `a = 155.35`（中性 128，**+27 偏品红**）、`b = 120.77`（**−7 偏蓝**）⇒ **问题起点在 ISP 侧（白平衡）**，不是网络引入的。
2. **ZDE++ 把色偏放大约 1.5～3.5 倍**：输出 `a = 167.88`（**+40**）、`b = 102.70`（**−25**）⇒ 画面上就是那层**整片强紫**（见 `S_D_chroma.png` / `S_A_it.png` 右列）。
3. **噪声远比想象的小**：本帧信号好（原图均值 53），ZDE++ 输出相对原图的局部噪声只放大约 **1.5×**（luma 0.95→1.41、`a` 0.64→0.93、`b` 0.42→0.66），**远不是上一场景（0.75 Lux、原图均值 10）那个 ~7×**。
4. **色偏幅度与放大倍数同源**：迭代越少色偏越小（2 迭代 `a=159.78 / b=116.23`，接近原图），但整体变暗（67.8）且暗部 SNR 更差（9.86）。

## 4. 四方向各自的判定

| 方向 | 判定 | 依据 |
|---|---|---|
| **A 迭代次数** | **8 迭代保持不动** | 暗部 SNR **12.96 最高**（4 迭代 10.63 / 2 迭代 9.86）；少迭代只换来"变暗 + 相对噪声更差" |
| **B 曲线衰减 k** | **冗余，不建议** | k=0.5（86.08 / SNR 10.88）与 4 迭代（85.30 / 10.63）**几乎等价** ⇒ k 只是迭代次数的另一种写法 |
| **C 曲线场 3×3 平滑** | **无效** | 与基线差 53.57 dB（几乎无变化）；原因是曲线场**上采样到 1080p 时已被双线性平滑** |
| **D 增强后色度降噪** | **唯一纯收益，但属新增处理级** | 亮度不变（126.33→126.44）而局部色度噪声 **−16 % / −17 %**（`a` 0.93→0.78、`b` 0.66→0.55）；⚠️ 采纳须走 §15 裁定 |

## 5. 结论与建议的下一步

**本帧的优化优先级应重排为：色偏 > 色度噪声 ≫ 亮度噪声/banding。**

- **首选方向：修 ISP 侧白平衡（根因）**，而不是在网后做色彩补偿 —— 契合 O54 的既有立场（「确需看清暗画内容的正确做法是修好链路本身，而非后处理」）。
  证据：原图 `a=155 / b=121` 已偏，网络只是放大它；**在源头校正，代价最小且不引入新处理级**。
- **次选：确认 ISP 侧是否为 AWB 在暗光下跑偏**（需只读回读 AWB 状态；IQ 中 `wb_v21` 子树的当前生效值未在本轮读取）。
- **色度降噪**（−16 %）可作为**候选新增级**，但在色偏未修好之前优先级低于前者。
- **不建议**：改迭代数、加曲线衰减、做曲线场平滑（分别：已最优 / 冗余 / 无效）。

## 6. 效力边界与残留

- **非验收依据**；**单帧 / 单机位 / 单照度（0.72 Lux 自然漫射光，用户口头）/ 单次采集**；**无 GT** ⇒ 全部指标是相对量与形态量，不是画质分。
- 「平坦区」由原图 Sobel 能量定义（**口径选择**）。
- **未做**：ISP 侧 AWB / 白平衡的可回读状态与生效值；多帧统计；别的照度/场景复测；色偏的**客观校正量**求解（需先定校正方式）。
- ⚠️ **红线**：本轮的 D 方向（色度降噪）是**方向探针**；若采纳即构成**交付链路新增处理级**，须先走 §15 裁定并定其**性能预算**与**契约落点**。

### 7.3 判定

1. **CSC / range 已排除**（§7.1）⇒ 色偏是 ISP 真实输出。
2. **最可能成因**：`defaultNightGain = [1.909, 1, 1, 1.999]` 本身即**品红偏置**（R 与 B 同时抬到 ~2×，G 保持 1×）——

   且 `wbGainClip.enable = 0` ⇒ AWB 输出**无增益裁剪保护**，低信噪比下更易跑偏。
3. ⚠️ **未能回读 AWB 的当前生效增益**：IQ、`rkaiq` 日志、`v4l2-ctl` 控制列表三处均不暴露（与 §10.4 `nr_3d_ref_frames` 记的同一情形）
   ⇒ **无法直接区分**「落到兜底增益」与「自动算出偏置增益」两种情形，二者修法不同。

### 8.3 ⭐ 结论

1. **根因确认**：把 `defaultNightGain` 改中性后，`LAB a` **143.7 → 128.5（≈中性 128）**、`R/G` **2.00 → 1.13**、中性像素 **0 % → 17.5 %**，
   而**亮度几乎不变**（36.6/37.3 vs 38.5/38.2）⇒ **改变只发生在色彩通道**。
   ⇒ **AWB 的实际输出增益 = `defaultNightGain`；而该兜底值 [R×1.91, G×1.0, B×2.00] 本身即品红偏置。**
   （至于是「低光兜底」还是「首帧种子未被更新」，不影响修法，未进一步区分。）
2. **解释了「为什么前几天不偏」**：前四帧场景的中性像素占比 39.7 %~93.8 %，AWB 有充分参考、**未落到该兜底值**；
   09-29 自然漫射光下场景中性像素极少、AWB 失去参考 ⇒ **落到兜底** ⇒ 品红。
3. **残留**：补丁组 `LAB b = 133.9/134.6`（偏黄 +6），对照组 `b = 125`（偏蓝 −3）⇒ 主因（`a` +16）已解决，**仍有轻微偏黄**，
   指向 CCM 或光源本身偏暖（未查）。
4. **修法明确且不需动交付链路**：把 `defaultNightGain` 改为中性或**按现场标定**（属 **ISP 侧 IQ 变更**，须走 §15 裁定）。
