## 2. 核心结果 —— 损失 ≈ 0.02 dB / 0.0003（实质无损）

| | **PSNR** | **SSIM** |
|---|---|---|
| **PT FP32**（`LOL_v1`，部署口径） | 23.7291 | 0.8361 |
| **板端 RKNN FP16** | **23.7507** | **0.8364** |
| **Δ（PT − 板端）** | **−0.0217 dB** | **−0.00032** |

**逐图分布（n = 100）**：

| 统计量 | Δ PSNR（dB） | Δ SSIM |
|---|---|---|
| 均值 | **−0.0217** | −0.00032 |
| 中位 | −0.0233 | −0.00026 |
| **std** | **0.0708** | 0.00045 |
| 极值 | **[−0.2864, +0.2782]** | [−0.00162, +0.00021] |
| **\|Δ\| 的 P95** | **0.1454** | — |
| 板端更高者 | **63 / 100** | — |

**结论** —— **移植 + 量化的端到端指标损失落在 ±0.02 dB / ±0.0003 量级**；板端在 63/100 上甚至略高，属 **FP16 舍入的偶然**，**不构成真实增益**。⇒ **该 FP16 移植对本项目「画质」不构成可察觉损失**。

**取证图**（`board_strip_{best,median,worst}.png`，**链路原样、无任何后处理**；自上而下 = Low / GT / PT-FP32 / 板端）—— 三档 Δ 下 PT 与板端**目视不可分**。

## 3. 与 O35 / O37 的关系（两问两答）

| 项 | 本档实测 | 关系 |
|---|---|---|
| **O35**（FP16 **逐算子**数值闸口超阈 9~18×） | 端到端 PSNR 仅差 **0.02 dB** | **不矛盾** —— 逐张量数值偏差可以很大，而图像域端到端指标几乎不动。**O35 的状态不因本档改变** |
| **O37**（耗时超 ≤2 s 预算） | 板端 **8.0 s / 张** | **复核成立** —— HQ 960×544 单帧 ≈8 s，远超预算 |

⇒ **本档不解任何 O 项**；两条 O 项状态维持。

## 4. ⚠️ 关键随行发现（两条硬约束）

### 4.1 板端部署权重 = **`LOL_v1`**，不是 `LOL_v2_real`

**实测依据** —— `docs/evidence/reports/M0-4/export_hq_960x544_lolv1.json`：`weights = …/LOL_v1.pth`，`weights_sha256 = 9b4810dc51322fab70be8658ee0ad1df64a54aa814497b7849767baa2ff32cd1`；`build_hq_960x544_fp16_tk232.json` 的 `quant = "fp16"`。

**连带影响** —— **O11** 的「M1 权重一经变更即全量重跑」判定，其对象应以**板端实际部署权重（`LOL_v1`）**为准，而非 Phase C 的设计默认起点（`LOL_v2_real`）。

### 4.2 ⚠️ 绝对指标被**泄漏抬高**，不得作画质验收依据

`LOL_V1.train ∩ LOL_V2_Real.test = **86/100**`（上游证据档 `L1-paper-baseline.md` §3.1 实测）⇒ 本批 100 张中 **86 张在板端权重的训练集内** ⇒ **23.75 / 23.73 是泄漏值**。

- **仅 Δ（移植损失）有效** —— 两侧**同权重、同泄漏**，系统偏差**相消**。
- **无泄漏对照** —— PT `LOL_v2_real` 部署口径 = **22.3180 / 0.8429**（**另一个权重，不得与板端并列比**）。
- ⇒ **不存在对 `LOL_v1` 无泄漏的 LOL 测试集**（实测 `LOL_V1.train ⊆ LOL_V2_Real.train ∪ LOL_V2_Real.test`）。要拿板端的**干净绝对画质**，**只能等 IMX415 自采域（V1）**。

## 5. ⚠️ 作废记录（如实登记）

**首版比对（已作废）** —— 曾以 `LOL_v2_real.pth` 做 PT 参考，得「Δ 跨度 **−16.12 ~ +9.80 dB**、板端平均高 **1.43 dB**」的异常分布。**经查 = 跨权重比对**（板端是 `LOL_v1`）⇒ **该组数字作废**，**不得引用**。用作废前的数据反推「移植损失大/小」均无效。

**方法论教训** —— **比对前必须先核实被比对模型的权重来源**（构建报告的 `weights_sha256`），不能按「项目默认权重」假定。
