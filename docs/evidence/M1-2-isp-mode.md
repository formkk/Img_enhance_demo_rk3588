## 1. 目的

主基准 §3.2 明文：**「IMX415 的 1080p@60 模式在 RK 平台可能是裁切/抽行而非 2×2 模拟 binning，'+6 dB' 不预写，以实测为准」**，并给出三步实验：

1. `media-ctl` / **驱动 mode table** 确认 1080p 模式是 **binning、subsample 还是 crop**；
2. 同照度、同增益下对比暗部 σ（ROI 标准差）与拖影；
3. 无论哪种 1080p 模式，演示一律锁 30 fps、曝光拉满帧周期。

**本档只闭合第 ① 步**（定类）。第 ② / ③ 步的处置见 §7。

## 2. 结论

**当前 1080p 采集走的是 IMX415 的 `Horizontal/Vertical 2/2-line binning`（相邻 2×2 相加，即 HADD + VADD + ADDMODE = binning 2/2）** ⇒ `camera.mode_class = "binning"`。

依据强度说明（**区分事实与判定**）：

- **事实（板上直接读数）**：取流期间 sensor 的 `0x3020 = 0x01` / `0x3021 = 0x01` / `0x3022 = 0x01`、`0x30D9 = 0x02` / `0x30DA = 0x01`（§4.2）。
- **判定**：这组值 = **binning 2/2 使能**。依据 = ① 驱动源码中**只有**半尺寸（`1932x1096` / `1284x720`，注释明写 *2/2-line binning*）的寄存器表把这三支寄存器置 1，**全部** `3864x2192` 全幅表均为 0 且不写 `0x30D9`；② Sony 官方「2/2-line binning」配置表**逐项同值**（§6）。
- **未主张**：本档**不主张**任何 SNR / 灵敏度增益数值（§3.2 明文「'+6 dB' 不预写」）；机理表述仅作方向说明（§6.2）。

## 3. 判据寄存器与语义

寄存器名取自驱动源码（`IMX415_ADDMODE = 0x3022`）与 Sony 官方配置表注释（`imx415寄存器配置简述` 所载的 IMX415-AAQR 官方设置表）：

| 寄存器 | 名称 | 语义 | 全幅（all-pixel）表取值 | binning 2/2 表取值 |
|---|---|---|---|---|
| `0x3020` | HADD | 水平方向相邻像素相加 | `0x00` | `0x01` |
| `0x3021` | VADD | 垂直方向 2 行相加 | `0x00` | `0x01` |
| `0x3022` | ADDMODE | 相加模式（binning 2/2） | `0x00` | `0x01` |
| `0x30D9` | DIG_CLP_VSTART | 数字钳位起始（binning 2/2 口径） | **未被模式表写入**（留全局默认 `0x06`） | `0x02` |
| `0x30DA` | DIG_CLP_VNUM | 数字钳位行数（binning 2/2 口径） | **未被模式表写入**（留全局默认 `0x02`） | `0x01` |
| `0x3031` | ADBIT（in） | `0x00` = 10 bit，`0x01` = 12 bit | 依档 | `0x00` |
| `0x3033` | SYS_MODE | 数据率档（`0x05` = 891 Mbps） | 依档 | `0x05` |
| `0x3028/29` | HMAX | 行周期（clock 数）：`1H = HMAX / 74.25 MHz` | `0x044C` = 1100 → **14.81 µs** | `0x0226` = 550 → **7.407 µs** |
| `0x3024/25` | VMAX | 帧内行数：`帧周期 = VMAX × 1H` | 依档 | 依档（本板 = `0x1194` = 4500） |
| `0x311A` | CHIP_ID | 可读性自检 | — | 板上 = `0xE0`（与 dmesg `Detected imx415 id 0000e0` 一致） |

**为什么必须取流中采样**：这几支寄存器由驱动的 `start_stream` 在 `s_stream=1` 时写入（模式寄存器组）。待机态读到的是**全局默认值**（`0x3022 = 0x00` / `0x30D9 = 0x06`）⇒ **待机读数不能用于模式判定**。本档两份读数并存（§4.1 / §4.2）正是为了留下这个对照。

### 4.2 取流中（`s_stream=1`）——**判定依据**

原始输出 = `docs/evidence/reports/M1-2/stream_readback.out`：

```
0x311A = 0xE0   0x3000 = 0x00   0x3002 = 0x00   0x301C = 0x00
0x3020 = 0x01   0x3021 = 0x01   0x3022 = 0x01
0x3024 = 0x94   0x3025 = 0x11   0x3026 = 0x00
0x3028 = 0x26   0x3029 = 0x02
0x3031 = 0x00   0x3033 = 0x05
0x30D9 = 0x02   0x30DA = 0x01
0x3050 = 0x1A   0x3051 = 0x00
0x3040 = 0x00   0x3041 = 0x00
```

逐项换算：`VMAX = 0x1194 = 4500`、`HMAX = 0x0226 = 550` ⇒ **1H = 7.407 µs**、**帧周期 = 4500 × 7.407 µs = 33.33 ms = 30.0 fps**（与 §4.4 的 30.00 fps 独立吻合）；`SHR0 = 0x001A = 26` ⇒ 积分时间 = `VMAX − SHR0 = 4474` 行 ≈ **33.1 ms**（≈1/30 s）；`SYS_MODE = 0x05`（891 Mbps）、`ADBIT in = 0x00`（10 bit，与 `bpp: 10` 一致）。

## 5. 交叉印证（驱动源码与官方配置表）

### 5.1 Rockchip BSP 驱动 `imx415.c`

来源 = `rockchip-linux/kernel` 的 `develop-5.10/drivers/media/i2c/imx415.c`（`DRIVER_VERSION = KERNEL_VERSION(0, 0x01, 0x08)`，**与板上 dmesg 的 `driver version: 00.01.08` 一致**；另取 `develop-6.1` / `develop-6.6` 的同名文件，**按寄存器表与模式表的关键行逐项比对结果一致**）。关键事实：

- **`0x3022 = 0x01` 只出现在 3 张表**：`imx415_linear_12bit_1932x1096_594M_regs`、`imx415_hdr2_12bit_1932x1096_891M_regs`、`imx415_linear_12bit_1284x720_2376M_regs_2lane`（后者表头注释：**`2568x1440 2/2-line binning & Window cropping`**）。
- **`0x30D9 = 0x02` + `0x30DA = 0x01` 同样只出现在上述 3 张表**；全部 `3864x2192` 全幅表为 `0x3022 = 0x00` 且**不写** `0x30D9/0x30DA`（`0x30D9 = 0x06` 仅出现在两张 global 表）。
- 读出的**半尺寸**（`1932×1096`）恰为 `3864×2192` 的两轴各半；驱动对 `cur_mode->width == 1944` 的模式把 **crop bounds 定为居中 `1920×1080`**（`imx415_get_selection`，与板上 `capture_mode is 1920x1080` 吻合）。
- 行周期口径（源码注释）：`1H period = (1100 clock) = (1100 × 1 / 74.25 MHz)` ⇒ 全幅 HMAX `0x044C` = 1100 ⇒ **1H = 14.81 µs**；板上取流中 `HMAX = 550` ⇒ **1H = 7.407 µs**，恰为全幅之半（与"水平读出减半"自洽）。**该条只作旁证**（`HMAX` 亦可因其它机制变化），**不作为主判据**。
- **⚠️ 已知差异（不得掩盖）**：本份公开源码里的 `1944` 模式是 `height = 1097, bpp = 12`，而板上是 `1096, bpp = 10`；板上 DT 另带公开分支**没有**的 `rockchip,imx415-capture-mode` 属性及其日志 `capture_mode is 1920x1080` ⇒ **板上驱动是另一份（SDK / 厂家）源码**。故本档**不以源码作唯一依据**，而以 §4.2 的**板上寄存器回读为主判据**。

### 5.2 Sony 官方配置表

来源 = IMX415-AAQR 官方设置表（`imx415寄存器配置简述` 所载 `IMX415-AAQR 2/2-line binning, CSI-2_4lane, 27MHz, AD:10bit, 891Mbps` 表），其逐行注释与板上取流读数对照：

| 寄存器 | 官方表（binning 2/2） | 板上取流中 | 一致性 |
|---|---|---|---|
| `0x3020` | `0x01` // HADD（horizontal binning） | `0x01` | ✅ |
| `0x3021` | `0x01` // VADD（vertical binning） | `0x01` | ✅ |
| `0x3022` | `0x01` // ADDMODE（binning 2/2） | `0x01` | ✅ |
| `0x30D9` | `0x02` // DIG_CLP_VSTART（binning 2/2） | `0x02` | ✅ |
| `0x30DA` | `0x01` // DIG_CLP_VNUM（binning 2/2） | `0x01` | ✅ |
| `0x3031` | `0x00` // ADBIT in（10bit） | `0x00` | ✅ |
| `0x3033` | `0x05` // SYS_MODE（891Mbps） | `0x05` | ✅ |
| `0x3028/29` | `0x226` // HMAX 550 clock | `0x0226` | ✅ |

**机理方向（不作结论、不写数值收益）**：2/2-line binning 使一个输出像素由 2×2 相邻像元共同贡献 ⇒ **有效像元由 1.45 µm 变为等效 2.9 µm**、**空间采样率（Nyquist）两轴各减半**；其 SNR 收益**须以 §3.2 第②步的实测为准**，本档不预写任何 dB 值。

### 8.2 口径定义（可复现；本口径由本次执行定义）

- **只用 Y 平面**（NV12 前 2,073,600 B 为 Y、后 1,036,800 B 为 UV）。
- **块** = 64×64，取**前 1024 行**（16 块行）× 全宽（30 块列）= **480 块**（尾部 56 行不参与）。
- **暗部块** = 该帧**块均值最小的 25%**（120 块）——按块均值排序取，不绑定固定阈值。
- **暗部块 σ** = 该帧暗部块的**块内标准差**取中位数；跨帧再取中位 / p90。
- **结构去除噪声代理** = `Y − 3×3 均值`（高通）在**暗部 25% 像素**上的 **σ**（去掉块内纹理/边缘对"噪声底"的污染）。
- **时域 |ΔY|** = 相邻帧同像素绝对差；另做**滞后测试**：`lag = 1 / 5 / 30 / 150 / 299` 帧的 |Δ| 分位数——**判据 = 纯时域独立噪声时 |Δ| 中位数与 lag 无关（≈1.128σ），缓慢漂移/运动则使尾部随 lag 增长**。
- **⚠️ 拖影（代理口径）** = 上述时域 |Δ| 的**空间均匀性 / 滞后不变性 / 傅里叶峰值**（用于判别"残影/局部运动/频闪"）。**真实运动拖尾需运动靶标 ⇒ 本项未做**（§8.5）。

### 8.4 解读与边界

1. **噪声底（推荐引用值）**：**≈ 6 LSB**（两个独立口径吻合——高通 σ = 6.02；由 `E|Δ| = 1.128σ` 与 |Δ| 中位 6 反推 σ_eff ≈ 5.3）。**"暗部块 σ = 9.12" 含块内结构/边缘，不宜当噪声底引用**（场景是真实房间：书架/包/墙，见 §8.1 直出帧）。
2. **时域残影/鬼影：未检出**。三条独立证据——① |Δ| 中位数**与 lag 无关**（纯时域独立噪声特征）；② 块级 |Δ| **空间高度均匀**（能量集中度 12.2% ≈ 均匀 10%）⇒ 不是局部运动/残影形态；③ 频谱**无频闪特征**。
3. **存在缓慢漂移（登记，不归因）**：全帧 Y mean 有 ≈1% 的慢变（0.1–0.6 Hz），使 |Δ| **尾部**随 lag 增长（p95 19@lag1 → 32–37@lag≥5）；**中位数不受影响** ⇒ 漂移不是 |Δ|≈6 的来源（帧间均值增量 ≈0.1–0.2 LSB，远小于 6）。**成因未查**（光照 / ISP 慢自适应 / 场景微动均可能，无对照）。
4. **纪律（不得越界）**：本档**不主张任何 SNR / 灵敏度收益数值**（§3.2「'+6 dB' 不预写」）——**6 LSB 是"当前条件下的基准确认值"，不是"binning 收益"**；若要把它折算成输入参考噪声或与其它模式比较，须另立实验（而"跨模式对照"已由 §7 的口径裁定取消）。
5. **用途**：供 §11 M1、§12 R10、U1 采集计划引用（同模式、同 IQ 档、同曝光/增益下的比较锚点）。
