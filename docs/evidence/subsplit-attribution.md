## 4. 归因

### 4.1 平均成本（P50）：**线性可加**

| 来源 | 增量（P50） |
|---|---|
| TH2a 曲线估计 | V1−V0 = **+1.37** |
| TH2b 增强应用 | V2−V0 = **+23.13** |
| OSD | V4−V3 = **+4.46** |
| 线性合计 | **+28.96** |
| 实测全开 | V4−V0 = **+27.92** |

⇒ 与线性预测吻合（差 1.0 ms）⇒ **P50 层面无争用**，均值成本即"各模块之和"。

### 4.2 尾部（P95）：**非线性超额**

| 来源 | 增量（P95） |
|---|---|
| TH2a | V1−V0 = **+5.02** |
| TH2b | V2−V0 = **+23.45** |
| est×apply 并发合计 | V3−V0 = **+38.87**（线性预测 28.47 ⇒ **超额 +10.40**） |
| OSD | V4−V3 = **+30.36**（O44 微基准三项合计 ≈ **12.05** ⇒ **超额 ≈ +18.31**） |
| 全开合计 | V4−V0 = **+69.23** |

### 4.3 五条结论

1. **平均成本可加、无争用**；**P95 超支来自尾部排队**（非线性超额约 **+29 ms**），不是单模块耗时。
2. **最大单点杠杆 = OSD**：**去掉 OSD（V3）端到端 P95 = 61.26 ms ⇒ 达标（≤80）**；加上 OSD（V4）= 86.97 ms ⇒ **OSD 一项即把该项从"过"推到"不过"**。且 OSD 的实测 P95 增量（30.36）**远大于**其函数级微基准（12.05，O44）。
3. **est 与 apply 并发有 +10.4 ms 的尾部超额**（P50 无超额）⇒ 属争用/排队性质。
4. **apply 路径自身分布极紧**（V2：P50 31.99 / P95 33.20 / max **33.7**，无长尾），但其帧窗增量 **23.45 ms** 远高于内核微基准（O42/O44 的 **3.985 ms**）⇒ **约 19 ms 的差额未分离**（疑缓存/带宽效应）。
5. **提交→vblank 段在 5 个变体中恒定 16.2~16.7 ms（max ≤24）** ⇒ **显示侧无嫌疑**，与 §15 O76「超支全在应用侧」一致。
6. fps 随负载略降（15.104 → 15.040），**仍 ≥14.99**；`60×0.010 = 0.6 ms/帧` 量级的余量被争用吃掉。

### 4.4 长尾的定位（新事实）

V0/V1/V3/V4 的 `app max` ≈ 0.96~1.09 s，逐帧定位（V4 第 3 轮）为**启动瞬态**：第 0~3 帧 **656.3 / 613.7 / 585.5 / 547.0 ms**，此后仅两处 ~105~113 ms 的偶发（第 170 / 232 帧）；V2 因剔除前 30 帧而未含该瞬态（其 max = 33.7）。

- **不影响本次比较**：瞬态仅 3~4 帧/轮（1.3%），而聚合 P95 的位置距顶端 **45 个样本** ⇒ **该瞬态不进 P95/P50**；V2 的 `--skip-first 30` 对 P95 的影响实测仅 **0.10 ms**（33.20 vs 33.30）。
- **与既有登记的关系**：O19 登记的"两侧共有 ~1.1–1.4 s 单次长尾"即此瞬态（空链路 `max` 1063.6 / 常态 1384.0），**本次把它定位到启动段**。

## 4.5 OSD 二级拆分（v3.86 追加 97，本轮补测）

上一节把 OSD 定为最大单点杠杆（P95 +30.36 ms）。本轮把 OSD 再拆成**「图示绘制」**与**「统计」**两级（钩子 `--osd-status-only` = 只画状态行、跳曲线图 / 直方图 / 图名；`--osd-no-stats` = `update_stats()` 直接返回）。

| 变体 | app P50 | app P95 | 端到端 P95 | 提交→vblank P95 | fps |
|---|---|---|---|---|---|
| **v4b** 全开（同批参照） | 36.23 | 79.84 | 87.62 | 16.31 | 15.068 |
| **s1** 只状态行（**保留统计**） | 33.19 | 78.37 | 85.72 | 16.58 | 15.016 |
| **s2** 只状态行 **+ 去统计** | 28.78 | **51.24** | **59.98** | 16.77 | 15.070 |

**结论（修正上一节的表述）**
1. **去掉两块图示几乎无收益**：ΔP95 = **−1.5 ms**、ΔP50 = −3.0 ms ⇒ 与 O44 微基准（曲线图 3.77 + 直方图 0.337 ≈ 4.1 ms）**量级一致** ⇒ **绘图不是 ①-2 超支的原因**。
2. **"统计"才是 OSD 增量的主体**：s1 → s2 的 ΔP95 = **−27.1 ms**（78.37 → 51.24）、ΔP50 = −4.4 ms；**s2 的端到端 P95 = 59.98 ms ⇒ 达标（≤80）**。
3. **机制假设被实测否定**：全开轮逐帧看，>45 ms 的帧占 **37.7%（113/300）**且**跨各段分布**（0–99 / 100–199 / 200–299 段分别 42 / 36 / 35 帧），**不是 1 Hz 周期突发**（那应为约 20 帧）⇒ 登记为**待查**。
4. **代码层线索（仅登记，未改）**：`main.py` 的调用为
   `self.disp.osd.update_stats(win.to_bytes(), enh.to_bytes(), WIN_W, WIN_H)` —— **两个 `to_bytes()` 每帧都会求值**（每帧两个 512×288×3 的 CPU 拷贝），而 1 Hz 节流发生在 `Stats.maybe_update()` **内部**。该结构**与"每帧付拷贝成本、尾部被抬高"相符**；**改法须先走 §15 裁定**（规则 `00-ssot.md` §4）。

## 4.6 O142 落地与实测（v3.86 裁定 O142；**含一次结论订正**）

**改动**（回调式，判据不外移）：`main.py` 改为 `update_stats(lambda: win.to_bytes(), lambda: enh.to_bytes(), …)`；`osd.py` 的 `Stats.maybe_update()` 在**到期之后**才调用回调 ⇒ **非到期帧不再产生两次 512×288×3 的 CPU 拷贝**；1 Hz 判定仍在 `Stats` 内唯一一处；`bytes` 直传入参保持兼容（板端自检：未到期帧取样次数不增加、`bytes` 直传仍返回 `True`）。

| 口径 | 端到端 P50 | 端到端 P95 | 采集→提交 P95 | 提交→vblank P95 | fps（窗口径） |
|---|---|---|---|---|---|
| `v4b` 全开（改动前，同批） | 46.00 | 87.62 | 79.84 | 16.31 | 15.068 |
| **`fix1` 改动后** | **43.94** | **82.21** | **71.88** | 16.34 | 15.075 |

逐轮 e2e P95 = 79.9 / 82.2 / 90.8；配对率 1.0、丢弃四项全 0、`stream_on_count` 三轮均 1。

**结论**：改动**真实有效但不足以收口**（P95 **−5.4 ms**，**仍 >80**）——与草案 §4 的预先声明一致（`s2` 是"完全不做统计"，本次只去掉非到期帧的拷贝，**每秒一次统计仍在**）。

### 4.6.1 订正：P95 确实由"1 Hz 统计帧"决定（前一节的否定结论**部分收回**）

对 `fix1` 第 3 轮逐帧核对（300 帧）：

- **>60 ms 的帧 = 23 帧（7.7%）** ⇒ **超过 P95 的 5% 分位占比** ⇒ **聚合 P95 落在这批帧内**（该轮 P95 = 76.6 ms）；
- **剔除这 23 帧后 P95 = 51.20 ms ≈ `s2` 的 51.24 ms**（完全不做统计）；
- 相邻间隔多为 1 帧（成簇），簇间可见 15 / 31 / 45 帧（≈ 1 Hz / 2 Hz / 3 Hz @ 15 fps 的整数倍），量级与"每秒一次统计"（约 20 次/轮）吻合。

⇒ **机制 = 每 1 秒一次的统计帧把约 7% 的帧抬高 ~25 ms（76.6 − 51.2），恰好越过 P95 分位**。§4.5 的结论 3（"1 Hz 周期突发被否定"）系**只看 >45 ms 的总占比（37.7%，含宽底分布）**所致，**此处订正**：宽底分布与 1 Hz 统计帧**并存**，而**决定 P95 的是后者**。

**一次统计的本体成本 ≈ 25 ms**（对 O44 微基准的 7.94 ms 有偏差，疑因帧内与 apply / OSD 并发、缓存被冲刷；**未进一步分离**）。

## 4.7 候选① 落地：统计下沉 native（v3.86 裁定 O142-候选①；**①-2 判过**）

**实现**：`native/osd_core.c` 新增 `osd_stats_rgb888()`（抽样 / 灰度权重 / 直方图 / 均值与 `Stats` **逐字同口径**）；pybind 暴露 `_n.osd.stats(raw, enh, w, h, decimate)` —— **直接吃两个 native 缓冲（零拷贝）**，直方图以 `256 × u32` 小端返回；`osd.py` 的 `Stats.maybe_update()` 到期后走 native 分支（回调式 / `bytes` 直传保留为对照与自检）；`main.py` 改传缓冲。**1 Hz 判据仍在 `Stats` 内唯一一处**。

**正确性（板端）**：native 与 Python 参考**逐位一致** —— 采样点数 `192 = 192`、均值 `127.1875000000 = 127.1875000000`、双直方图 256 项全等；未到期帧不取样；`bytes` 直传兼容。**构建零告警**（`warning` 计数 0）。

| 口径 | `v4b`（改动前） | `fix1`（回调式） | **`fix2`（native）** |
|---|---|---|---|
| 端到端 P50 | 46.00 | 43.94 | 46.22 |
| **端到端 P95** | 87.62 | 82.21 | **64.92** |
| 采集→提交 P95 | 79.84 | 71.88 | **51.68** |
| 提交→vblank P95 | 16.31 | 16.34 | 16.56 |
| fps（窗口径，中位） | 15.068 | 15.075 | 15.075 |

逐轮 e2e P95 = **64.5 / 65.8 / 64.9**（三轮全部 ≤80）；配对率 1.0、丢弃四项全 0、`stream_on_count` 三轮均 1。

**结论**：**①-2 判过**（P95 **64.92 ≤ 80**，余量 15.1 ms）；采集→提交段 P95 79.84 → **51.68**（−28.2 ms），与"统计帧被消除"的预期一致。**判据与契约零改动、不放宽任何上限、`config.yaml` 零改动。**
