## 4. 归因

### 4.1 平均成本（P50）：**线性可加**

| 来源 | 增量（P50） |
|---|---|
| TH2a 曲线估计 | V1−V0 = **+1.37** |
| TH2b 增强应用 | V2−V0 = **+23.13** |
| OSD | V4−V3 = **+4.46** |
| 线性合计 | **+28.96** |
| 实测全开 | V4−V0 = **+27.92** |

⇒ 与线性预测吻合（差 1.0 ms）⇒ **P50 层面无争用**，均值成本即"各模块之和"。

### 4.2 尾部（P95）：**非线性超额**

| 来源 | 增量（P95） |
|---|---|
| TH2a | V1−V0 = **+5.02** |
| TH2b | V2−V0 = **+23.45** |
| est×apply 并发合计 | V3−V0 = **+38.87**（线性预测 28.47 ⇒ **超额 +10.40**） |
| OSD | V4−V3 = **+30.36**（O44 微基准三项合计 ≈ **12.05** ⇒ **超额 ≈ +18.31**） |
| 全开合计 | V4−V0 = **+69.23** |

### 4.3 五条结论

1. **平均成本可加、无争用**；**P95 超支来自尾部排队**（非线性超额约 **+29 ms**），不是单模块耗时。
2. **最大单点杠杆 = OSD**：**去掉 OSD（V3）端到端 P95 = 61.26 ms ⇒ 达标（≤80）**；加上 OSD（V4）= 86.97 ms ⇒ **OSD 一项即把该项从"过"推到"不过"**。且 OSD 的实测 P95 增量（30.36）**远大于**其函数级微基准（12.05，O44）。
3. **est 与 apply 并发有 +10.4 ms 的尾部超额**（P50 无超额）⇒ 属争用/排队性质。
4. **apply 路径自身分布极紧**（V2：P50 31.99 / P95 33.20 / max **33.7**，无长尾），但其帧窗增量 **23.45 ms** 远高于内核微基准（O42/O44 的 **3.985 ms**）⇒ **约 19 ms 的差额未分离**（疑缓存/带宽效应）。
5. **提交→vblank 段在 5 个变体中恒定 16.2~16.7 ms（max ≤24）** ⇒ **显示侧无嫌疑**，与 §15 O76「超支全在应用侧」一致。
6. fps 随负载略降（15.104 → 15.040），**仍 ≥14.99**；`60×0.010 = 0.6 ms/帧` 量级的余量被争用吃掉。

### 4.4 长尾的定位（新事实）

V0/V1/V3/V4 的 `app max` ≈ 0.96~1.09 s，逐帧定位（V4 第 3 轮）为**启动瞬态**：第 0~3 帧 **656.3 / 613.7 / 585.5 / 547.0 ms**，此后仅两处 ~105~113 ms 的偶发（第 170 / 232 帧）；V2 因剔除前 30 帧而未含该瞬态（其 max = 33.7）。

- **不影响本次比较**：瞬态仅 3~4 帧/轮（1.3%），而聚合 P95 的位置距顶端 **45 个样本** ⇒ **该瞬态不进 P95/P50**；V2 的 `--skip-first 30` 对 P95 的影响实测仅 **0.10 ms**（33.20 vs 33.30）。
- **与既有登记的关系**：O19 登记的"两侧共有 ~1.1–1.4 s 单次长尾"即此瞬态（空链路 `max` 1063.6 / 常态 1384.0），**本次把它定位到启动段**。

## 4.5 OSD 二级拆分（v3.86 追加 97，本轮补测）

上一节把 OSD 定为最大单点杠杆（P95 +30.36 ms）。本轮把 OSD 再拆成**「图示绘制」**与**「统计」**两级（钩子 `--osd-status-only` = 只画状态行、跳曲线图 / 直方图 / 图名；`--osd-no-stats` = `update_stats()` 直接返回）。

| 变体 | app P50 | app P95 | 端到端 P95 | 提交→vblank P95 | fps |
|---|---|---|---|---|---|
| **v4b** 全开（同批参照） | 36.23 | 79.84 | 87.62 | 16.31 | 15.068 |
| **s1** 只状态行（**保留统计**） | 33.19 | 78.37 | 85.72 | 16.58 | 15.016 |
| **s2** 只状态行 **+ 去统计** | 28.78 | **51.24** | **59.98** | 16.77 | 15.070 |

**结论（修正上一节的表述）**
1. **去掉两块图示几乎无收益**：ΔP95 = **−1.5 ms**、ΔP50 = −3.0 ms ⇒ 与 O44 微基准（曲线图 3.77 + 直方图 0.337 ≈ 4.1 ms）**量级一致** ⇒ **绘图不是 ①-2 超支的原因**。
2. **"统计"才是 OSD 增量的主体**：s1 → s2 的 ΔP95 = **−27.1 ms**（78.37 → 51.24）、ΔP50 = −4.4 ms；**s2 的端到端 P95 = 59.98 ms ⇒ 达标（≤80）**。
3. **机制假设被实测否定**：全开轮逐帧看，>45 ms 的帧占 **37.7%（113/300）**且**跨各段分布**（0–99 / 100–199 / 200–299 段分别 42 / 36 / 35 帧），**不是 1 Hz 周期突发**（那应为约 20 帧）⇒ 登记为**待查**。
4. **代码层线索（仅登记，未改）**：`main.py` 的调用为
   `self.disp.osd.update_stats(win.to_bytes(), enh.to_bytes(), WIN_W, WIN_H)` —— **两个 `to_bytes()` 每帧都会求值**（每帧两个 512×288×3 的 CPU 拷贝），而 1 Hz 节流发生在 `Stats.maybe_update()` **内部**。该结构**与"每帧付拷贝成本、尾部被抬高"相符**；**改法须先走 §15 裁定**（规则 `00-ssot.md` §4）。
