## 0. 结论速览（推荐路线）

**推荐：以「乙（有监督微调，用 B 的 60 对 GT）」为主，叠加少量「甲（零参考）正则项」的混合路线。**

理由（详见 §2/§3）：
1. 内核施加语义已翻为**保色比提亮**（见 `docs/design/realtime_apply.md` §3.1；主基准 §14 追加 157 / 159），该语义**每个像素只有一个标量增益 `k`**（实现见 `native/apply_core.c`）⇒ 内核把曲线估计网络**限成一条「亮度曲线」**——监督项只能、也只应训「亮度匹配」，与乙天然一致；

3. 甲用的 C 单边图与乙的 B 是**同一批帧**（`~/datasets/imx415_zde_train60/list.json` 的 note 明写「与 B 的同一帧」）⇒ 甲相对乙**没有数据优势**，只作正则。

## 1. 背景与硬前提（以代码为准）

### 1.1 实时路结构

- 链路：TH1 采集 → TH2a `CurveEstimator`（RGA 下采样 → ZDE++ 曲线估计 NPU → EMA → 双缓冲发布）→ TH2b `realtime_apply.apply_window`（单遍融合，迭代次数为契约常量，见 §3.3 / §4.1）。
- 曲线档 / 估域有效区 / 应用域：**取值一律见 §3.1 契约与 §10.4 键表**（本文不复述）。
- 权重：官方 ZDE++ 权重的路径与哈希随行记录，以实测为准（本轮复核）。

### 1.2 ⭐ 施加语义 = 保色比提亮（训练目标必须与之一致）

- 裁定：主基准 §14 **追加 157**（逐通道 → 保色比提亮）、**追加 159**（翻为交付默认，反向 opt-out 为 `--no-preserve-ratio`，**非 config 键**）；设计记录见 `docs/design/realtime_apply.md` **§3.1**。
- 实现（唯一权威）：`native/apply_core.c` —— 曲线场输入 `v` = **三通道均值**（`vmean`）；亮度 `L` 用 **BT.601 三元式**（系数见该文件 `luma_coeffs`）；`L2 = f^N(L, v)`；`k = (L==0) ? 0 : L2/L`（快速倒数）；三通道按 `k` **同比缩放**，输出 clip 后 8-bit 量化（`store_group4`）。**逐项数值与行号以该文件为准，本文不复述**。
- 默认开启：`realtime_apply.py` 的 `configure` / `configure_from_config`（`preserve_ratio` 默认见该文件）。
- **推论（关键）**：保比语义下，曲线场**只有三通道均值被消费**（`vmean`）⇒ 网络 3 通道输出的**通道间差异被丢弃**，有效自由度 = **1 条亮度增益场**。这直接决定 §2.2 的「保色比损失」几乎恒零、以及「色彩恒常项」与内核语义冲突。

### 1.3 可训练部分（梯度能否到曲线估计器）

- 网络定义（仅转换期使用）：`tools/zde_model.py` —— `enhance_net_nopool` 的曲线估计器输出 `x_r`；`enhance()` 是**纯 PyTorch 逐点运算的迭代复合 ⇒ 可微**；`CurveEstimator` **只导出曲线估计部分**（输出 3ch `x_r`），板端迭代在 `apply_core.c` 里做。
- ⇒ **梯度能回传到曲线估计器**（训练在 PyTorch 内用可微前向）。
- **但板端施加内核 `apply_core.c`（C/NEON）不可微** ⇒ 训练时必须**自写一个「保比语义」的 PyTorch 等价前向**（复刻 §1.2 的 `vmean`→`L`→`f^N`→`k`→同比缩放→clip），否则**训练/部署语义错配**。
- 先例：本项目已做过 ZDE++ 的**监督**微调（`refs/pre-research/m0_zde_finetune_v2.py`，可微损失），证明该路径可跑通（该脚本为**旧逐通道语义**版本，**不能直接复用**，只证明可微性与工程可行性）。

## 2. 微调目标与损失（定义式 + 待标定量 + 标定方法）

记输入暗图为 `x`（[0,1]，RGB，保比前），训练用可微前向输出 `ŷ`，GT 为 `y`（B 对）。

### 2.1 有监督项（用 B 的 GT）

| 项 | 定义式 | 出处/依据 | 待标定量 + 标定方法 |
|---|---|---|---|
| **L1** | `L1 = mean(|ŷ − y|)` | 官方/既有微调惯例（`m0_zde_finetune_v2.py`；`tools/l1_finetune.py`） | 无系数（= 1 基线）；先只训 L1 作「下界臂」 |
| **Charbonnier** | `L_ch = mean( sqrt((ŷ−y)² + ε²) − ε )` | 平滑 L1，抗噪 | **ε 待标定**：扫 `{1e-1,1e-2,1e-3}` × [0,1] 域，取「val L1 最优且无过平滑」的点；标定集见 §4 |
| **亮度对齐** | `L_bright = (mean(ŷ) − mean(y))²` 或 `|·|` | **必须**（既有教训：训练池 GT 偏亮会把输出拉走，`docs/evidence/L1-finetune.md` §6） | **权重 λ_b、目标亮度锚**：先统计 B 的 GT 亮度（中位/分布）作为锚；λ_b 用「先 0 → 逐步加到输出亮度偏移 `mean(ŷ)−mean(y)` 收敛到 ≈0」的二点试凑（先定号、后定量） |
| （可选）**可微 SSIM** | `1 − SSIM(ŷ,y)` | `m0_zde_finetune_v2.py` | 权重 λ_ssim 待标定（与 L1 网格 1/2 层） |

> ⚠️ **先标定「B 的 GT 亮度锚」再训练**（§8 步骤 1），否则重复 `L1-finetune.md` §6 的坑。

### 2.2 保色比项（与内核语义一致）

| 项 | 定义式 | 待标定量 + 标定方法 |
|---|---|---|
| **保色比偏差（逐像素）** | `Δ_ratio = mean( |(R/G)_ŷ − (R/G)_x| / (R/G)_x ) + 同 B/G` | 无系数（度量式） |
| **削顶/饱和惩罚（唯一有效的「保比」损失）** | `L_clip = mean( relu(ŷ−1) + relu(−ŷ) )` 或对 `k` 上限软惩罚 | 权重 λ_clip 待标定 |

⭐ **关键判断（必须写清，否则会误用）**：在**保比内核**下，`ŷ = x·k`（`k` 为标量/像素）⇒ 对**未削顶像素** `(R/G)_ŷ ≡ (R/G)_x`，**Δ_ratio ≡ 0，梯度≈0**。因此：

- 「保色比偏差」**不是**有效的训练损失，而是**验收指标**（§5 ②）；
- 训练里想「保比」，只能惩罚**削顶**（`L_clip`）——因为**削顶是保比链上唯一会破坏色比的环节**（`store_group4` 对缩放后通道各自 clip 到 [0,1]）；
- 若仍要「色彩恒常」正则，**只能用 §2.3 的官方 `L_color`**，但它与保比内核**语义冲突**（它想改三通道均值差，而 `k` 标量根本改不了色比）⇒ 建议**停用或改口径**（见 §2.3）。

### 2.3 零参考正则（用于 C 的单边图；沿用官方损失族）

官方损失与参考量级（`refs/pre-research/zde/extracted/Zero-DCE_extension-main/Zero-DCE++/Myloss.py` 与 `lowlight_train.py`，**仅作起点，非本方案取值**）：

| 项 | 定义 | 官方出处 | 官方权重（起点） | 待标定量 + 标定方法 |
|---|---|---|---|---|
| **TV（平滑照明/增益场）** | `L_TV(x_r)` | `Myloss.py` | 官方 1600 | λ_TV：从官方值起，按「曲线场总变差 vs 噪声」扫 2~3 点；口径 = 对**单个 `vmean` 曲线场**（保比下唯一被消费的通道） |
| **空间一致性** | `L_spa(ŷ,x)` | `Myloss.py` | 官方 1 | λ_spa：官方值起点 |
| **色彩恒常** | `L_color(ŷ)` | `Myloss.py` | 官方 5 | ⚠️**与保比内核冲突 ⇒ 建议停用或改写为「增益场平滑」口径**；若启用须说明理由 |
| **曝光控制** | `L_exp(ŷ, E)`，patch 大小见 `Myloss.py` | `lowlight_train.py` | 官方 10，`E=0.6` | **E（目标均值）待标定**：按现场目标亮度标定（不要照抄官方 `0.6`）；λ_exp 官方值起点 |

> 官方 `enhance()`（`tools/zde_model.py`）是**旧逐通道语义**；训练 C 的零参考版**也须**换成 §1.2 保比语义前向。

## 3. 两条路线对比与推荐

| 维度 | 甲：零参考微调（只用 C 单边图） | 乙：有监督微调（用 B 的成对 GT） |
|---|---|---|
| 数据 | C（= B 的 dark，**同帧**，见 `~/datasets/imx415_zde_train60/list.json` note） | B（成对 dark+gt，见 `~/datasets/imx415_hq_train60/pairs.json`） |
| 损失 | 官方零参考族（TV/spa/color/exp） | L1/Charbonnier + 亮度锚（+可选 SSIM），可叠零参考正则 |
| **可量化性** | **弱**：无 GT ⇒ 只有相对/形态量（SNR、σ、色比，均需他处对拍） | **强**：PSNR/SSIM/亮度偏移，与 A 直接对拍（有 **1003A** 先例数字，见 `~/datasets/weights_index.json`） |
| 与「内核已改保比」一致性 | **冲突**：保比内核只改亮度，而零参考的 `L_color` 想改色彩；且保比使「色彩恒常」近乎无从优化 | **一致**：保比内核 = 亮度曲线 ⇒ 监督项训「亮度匹配」正好对位 |
| 主要风险 | 无法量化「是否更好」，只能与官方 ZDE++ 正/负对拍 | 受「训练池 GT 偏亮拉走」教训约束（`L1-finetune.md` §6）⇒ 须加亮度锚 |
| 结论 | **退路**（若 B 的 GT 被证不可信时） | **主线** |

**推荐：乙为主 + 甲作正则（TV/曝光小权重）。** 一致性论证：内核已翻**保色比提亮**（§14 追加 159），输出被限成「一条亮度曲线」⇒ **(a)** 监督项设 L1 + 亮度对齐项即与内核同目标；**(b)** 零参考的**色彩恒常项必须停用**（否则白耗容量、且不可优化）；**(c)** 「保色比」本身由内核构造性保证，只需在验收层量化（§5 ②），**不作训练损失**。

## 5. 可量化验收体系（核心交付）—— 四层 + 目视

> 统一「对拍法」：**同帧、同口径、同脚本**，对拍臂 = 官方 ZDE++ / 新权重 / identity（暗帧原样）**三臂**；所有数字必须能由本节命令一键重跑。
> **判据一律「待 §15 裁定」** —— 本节**不凭空给阈值**，只给口径与复现方式（参考主基准 §13 各行的复现方式）。

### ① 重建质量（对 A 的 GT）：PSNR / SSIM

- 几何口径、指标定义（PSNR 全通道 [0,1] / SSIM 逐通道 11×11 高斯 / 亮度与亮度偏移）**一律照 `~/datasets/imx415_public17/eval_public17.py` 的既有口径**（本文不复述数值）。
- ⚠️ **对零参考模型是否适用**：ZDE++ 无 GT 训练 ⇒ PSNR/SSIM 只作**代理量**；且保比内核**只改亮度** ⇒ 该两指标主要反映**亮度匹配度 + 结构**，不能反映色彩正确性。**替代/补充**：同报「亮度偏移 Δ_bright」与 identity / 官方 ZDE++ 对拍。
- **判据**：待裁定；**建议目标口径**（非取值）＝「相对官方 ZDE++ 不劣化、相对 identity 有增益」。

## 7. 风险与前置

1. **梯度回传**：可到曲线估计器（§1.3）；**内核不可微** ⇒ 训练用**自写的保比 PyTorch 前向替代**，偏差来源 = FRECPE 快速倒数、双线性采样、8-bit 输出量化 ⇒ **必须做转换损失核对**。
2. **导出/部署链**：PyTorch → ONNX → RKNN（toolkit / env 见 `docs/evidence/hq-weight-ab-0928.md`、§14 追加 168）→ 板端；`tools/convert_models.py` 支持曲线档 shape。**须有「转换损失核对」**（同批帧、PT FP32 vs RKNN，口径与 `docs/evidence/board-fp16-porting-loss.md` / `hq-weight-ab-0928.md` 同族，判据按该族阈值）。
3. **一度被证否的点（勿重踩）**：
   - **多帧时序平均（O149）**：演示档 IQ（3DNR 开）下**近乎无效**、**已封死**（`docs/evidence/gain-sweep-0927.md`；§15 O149）。仅在采集档（3DNR 关）下按 √N 有效（`docs/evidence/O87-lowlight-limit.md`）。
   - **网后色度降噪级**：`rt-zde-optimize-0929.md` 的 D 方向属**新增处理级**，须先走 §15 裁定。
   - **改迭代数 / 曲线衰减 / 曲线场平滑**：分别判「已最优 / 冗余 / 无效」（`docs/evidence/rt-zde-optimize-0929.md`）。
4. **保比内核的 3 通道冗余**：只消费 `vmean`（§1.2）⇒ 3 通道 head 有 2/3 容量被丢。**是否改单通道 head = 内核/契约变更**（改 `apply_core.c` 与 ONNX 输出），**须先走 §15 裁定**，本方案不裁定。
5. **权重变更触发 O11**：一旦上板即触发 **O11 全量重跑**（§10.5）。**未过 §11.2 转换闸口、未上板前不得称「成功」**。
6. **互斥/已见**：A ∩ B = ∅；A 对 HQ 权重族（E）部分已见（§4.1）。
7. **无 GT 的诚实性**：A 是**有 GT 的 HQ 成对集**，用其 GT 评 ZDE++ 属**跨路代理监督**，须在报告声明。
