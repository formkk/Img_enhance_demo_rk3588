## 0. 缘起（实测事实）

§14 追加 186 / 187 的实测结论：

| 事实 | 出处 |
|---|---|
| **实时路微调只改变了亮度，未改变噪声 / 彩斑** | §14 追加 186 / 187 |
| **根因 = 内核能力上限**：施加内核是「保色比提亮」= **逐点亮度曲线**（`k` 为标量、无邻域）⇒ **天生不能去噪 / 去彩斑 / 恢复细节** | §14 追加 183 / 186；`docs/design/zde_finetune.md` §1.2 |
| 用 PSNR/SSIM 判"画质"是**有偏的**（它奖励"贴 GT 的亮度"，把亮度一改就能大幅刷分） | §14 追加 186 / 187 |

⇒ **所以要治噪声 / 彩斑，必须"新增空间级"，而不是继续调权重** ⇒ 下面两条候选即为此时登记。

## 1. 方法 1（首选，改动最小）：ISP 侧降噪强度

| 项 | 内容 |
|---|---|
| **做什么** | 调整 ISP 侧已有降噪级的**强度参数**：**CNR（色度降噪）** / **YNR** / **2DNR（`bayernr`）** / **3DNR 强度（`bayertnr_v2` 的 hi/lo）** |
| **在哪** | **网前（ISP / IQ）** |
| **成本** | **低** —— 纯 IQ 键值改动（不新增处理级、不改代码） |
| **对症** | **CNR 正对「彩斑」（色度噪声）** ✓；YNR/2DNR/3DNR 对亮度噪声 |
| **为什么排第一** | 改动最小、可回退、且**彩斑是当前最扎眼的问题** |

## 2. 方法 2（次选）：网后"只滤高频色度"

| 项 | 内容 |
|---|---|
| **做什么** | 在实时路输出后做 **Y/C 分离**，**只滤 C 的高频分量**（保留亮度细节与低频色比） |
| **在哪** | **网后（实时路输出侧）** |
| **成本** | **低** —— 应用域仅 **512×288**，算力开销小 |
| **对症** | **彩斑最对症** ✓ |
| **可用的具体手段** | 以"原图"为引导的**导向滤波（guided filter）**、双边滤波、或（若在板端）RGA / 轻量卷积 |

## 3. 两条必须同时考虑的边界

| # | 边界 | 说明 |
|---|---|---|
| **(a)** | **属「新增处理级」⇒ 走 §15** | 无论方法 1（虽是 IQ 键值，但强度变更属契约级）还是方法 2（新增级），**都须先裁定再动手**；方法与阈值**均须裁定**，本档不代拟 |
| **(b)** | **须与已定稿的「保色比提亮」语义协同** | 若滤波改动了**低频色比**，就违反"保色比"语义 ⇒ **必须"只滤高频色度、保低频色比"** |

## 4. 现成验收口径（不必造尺子）

落地时"有没有效"有现成的可量化判据（出处 = §14 追加 187）：

| 指标 | 现有实现 |
|---|---|
| **平坦区 σ / 均值** | `tools/color_ratio_review.py` |
| **色度 σ(R−G) / σ(B−G)** | 同上（平坦区内） |
| **暗部块 σ / 均值** | 同上（暗部口径 = `realtime_frame_review.py:129-159`） |
| **保色比（R/G、B/G 相对偏差中位）** | 同上 |
| **削顶占比（分通道）** | 同上 |
| **性能（P95 ≤ 80 ms）** | 既有 §13 判据 |

⚠️ **跨亮度比较必须用归一化量**（σ/均值、色度σ÷平均亮度）—— 绝对 σ 随亮度单调上升，**不可直接比**（§14 追加 187 的教训）。
