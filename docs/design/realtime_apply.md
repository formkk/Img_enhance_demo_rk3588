## 1. 模块职责与边界

`realtime_apply` 是**纯计算库**，对应 §10.3 的 `realtime_apply.py`（C/NEON + pybind11 实现）。

| 项 | 设计选择 |
|---|---|
| 入口 | 两个：窗分辨率入口与满幅入口；**签名与返回码逐字以 §5 契约 C 表 + A 节为准**，本文不复述 |
| 调用方 | TH2b 调窗分辨率入口（实时链路）；TH3 作为编排者调满幅入口（§8.3 集合 B 存盘） |
| 不做 | 不做 I/O、不做 DRM、不做 NPU 推理；**不持 DMABUF 所有权、不 `close(dmabuf_fd)`**（§5 硬契约） |
| 状态 | **无状态、可重入**（§5 契约 C 表）：曲线场由参数传入，模块自持缓存为零 |
| 并发 | 两个入口可被 TH2b 与 TH3 并发调用 → **禁止模块级可变全局**；中间缓冲由调用方提供或函数内局部分配，不允许共享 scratch 复用 |
| 生命周期 | 曲线场的双缓冲发布/读取归 TH2a/TH2b（§5 数据契约）；本模块只读入一份已发布的完整视图 |

## 2. 编译期与运行期边界

- 语言标准、构建系统、产物与 ABI：见 `docs/build.md` §1 / §2 / §4。
- NEON 选项与 `-ffast-math` 的**适用范围**见 `docs/build.md` §3；本模块不得扩大该范围（对齐相关路径的禁用条件一并适用）。
- pybind11 层只做参数校验、类型转换与（必要时）GIL 处理，**计算全部在 C/NEON 内**；模块后缀与版本锁定按 `docs/build.md` §4，禁止手工命名。
- 热路径**不分配**（无逐帧 `malloc`）；缓冲由调用方传入，与 §6.1 的函数级打点口径一致。

## 3. 单遍融合：核心不变量

**不变量**：一次载入源像素 → 在寄存器/局部缓冲内完成全部曲线迭代 → 一次写出目标像素。

- 迭代次数为**契约值**，见 §3.3 与 §4.1（本文记作 `N_iter`，不复述数值）。
- 曲线场在 `N_iter` 次迭代中**复用同一份**（§4.1），不得逐迭代重采样或重换算。
- **禁止**"每迭代独立读写一遍"的直观写法：§3.3 已给出其 DDR 代价并判定为**未达标**，且不得以"编译器会自动优化"免检（非优化项，规则 `30-board-safety.md` §3）。

## 4. 曲线场双线性采样（融合进同一循环）

- 采样算法、归一化坐标口径、边界策略、显示域与存盘域同策：**一律见 §3.1 契约第 3 条**（本文不复述公式）。
- **不生成独立上采样曲线图**（§3.1 契约第 3 条明令）；不得用"先上采样到应用域、再迭代"的两段结构。
- **设计选择（性能关键）**：曲线场在迭代中不变，故**每个目标像素在进入迭代前只采样一次**（采样次数 = 像素数，而非像素数 × `N_iter`）；采样结果驻留局部变量。
- 采样计入 §6.1 的"曲线应用"行内，**不新增预算行、不重复计数**（§3.1 契约第 4 条）；microbenchmark 必须按"含采样"的实现复测。
- 边界（clamp）与 stride 无关：采样坐标由应用域 `w/h` 归一化产生，与 §5 无关。

## 5. 数据布局与 stride

- 应用域 stride 对齐的硬约束见 §3.1（RGA 输出 stride 与 RKNN 期望 `w_stride` 一致）；本模块**不对 stride 做任何假设**，行前进一律按调用方传入的 stride，禁止按 `w × 3` 推算。
- 满幅入口的输入格式与输出格式按 §5 契约 C 表；**Y 通道 only 属备选优化**（§9.7），是否启用由 M2 性能结论决定，本文档不锁定。
- 显示域与存盘域**共用同一内核**，仅以 `w/h/stride` 与精度参数区分；两域各自独立，不互相改写。

## 6. 精度分策（U8 / FP16）

- 分档规则（哪一档用哪种精度）见 §3.1 契约第 3 条与 §5 契约 A 节。
- `pipeline.curve_field_precision` 的**定稿值尚未落定（O23，M0-2 实测确认）** → 实现必须**同时支持两种精度并由 config 选择**，**禁止在代码里写死任一种**（规则 `00-ssot.md` §3.2）。
- **中间计算域**：设计选择为统一在 `float32` 中间域完成迭代，仅在曲线场的存取处体现 U8 / FP16 表示差异——避免迭代中累积半精度误差，并使两档共用同一内核结构。该选择须通过 §11.2 的 U8 / FP16 数值一致性检查。
- U8 档须过量化误差闸口（逐像素 diff + 盲评，见 §3.1 / §13）；**未过则该档回退 FP16**，回退动作按 §10.5 矩阵的降级口径记录。

## 7. 性能可测性

- 函数级打点与显示 FPS **分开上报**（§6.4 / §6.5）；打点区间**含采样**。
- 提供"单档 × 单 shape × 单精度"的可重复调用入口，供 `bench.py` 分轮 microbenchmark（M0-2 三档耗时、M0-13 DDR 流量确认）。
- 预算目标与超预算处置见 §6.1 / §6.2 与 §10.5 矩阵（本文不复述数值）。

## 8. 与 `docs/build.md` 构建验证清单的对应

每次构建按 `docs/build.md` §5 执行；其中与本模块直接相关的两项：**导出签名与 §5 契约 C 表逐字一致**、**U8 / FP16 两档数值一致性检查**（§11.2 的 ONNX↔RKNN 对齐回归子项）。

## 9. 明确不做（反模式清单）

1. 1080p 满幅的实时迭代（§3.1 核心原则：显示链路只做到窗分辨率）。
2. 独立上采样曲线图与全局查表（§5 TH2b：全局查表对空间变化的曲线场无效）。
3. CPU 全帧混合（§3.5 明令禁止）。
4. 逐迭代独立读写（§3.3 判为未达标）。
5. 模块内自持曲线场缓存或缓冲池（破坏无状态/可重入）。
6. 按 shape 直接推定精度档（O23 须由实测支撑）。
