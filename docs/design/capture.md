## 1. 职责与边界

`capture` 对应 §10.3 的 `capture.py`，是 **TH1 单线程内的实现**，同时承担采集与控制两职。

| 项 | 设计选择 |
|---|---|
| 拥有 | **DMABUF 池与 `QBUF` 权的唯一持有者**（§5 硬契约）；`seq` 分配者；`buffer_index + generation` 维护者；lease 签发者 |
| 兼管 | 触控 evdev / GPIO 按键 / 定时器 / 串口四源输入，共用一套触发 FSM（§8.1） |
| 对外 | 接口签名与返回码逐字以 §5 契约 C 表 / A 节为准，本文不复述 |
| 不做 | 不做显示、不做曲线估计与应用、不做 HQ 推理；**不做 ISP 预设切换**——运行期只允许曝光/增益微调，且经 `isp_ctl` 模块（§8.1 裁定 O10） |

## 2. DMABUF 池的对象模型

- 池深为契约值，见 §5 TH1（本文不复述）。
- 每个缓冲的身份 = **`buffer_index` + `generation`**；`generation` 在每次 `QBUF` 时自增（§5 契约 B：防旧引用误释放新一代缓冲）。
- **lease**：TH1 为"实际接收该帧的每个消费者"各签发一个 lease（TH2a / TH2b / TH3），`lease_id` 唯一（§5 契约 B）。
- 归还校验：`release_lease()` 必须校验 `lease_id` 是否属于当前在途集合；**不属于则返回 `E_STATE` 且不做任何引用计数变更**（防旧 lease 误减计数导致提前复用）。

## 3. lease 生命周期（本模块最关键的不变量）

```
QBUF 前的空闲缓冲
   └─(TH1 DQBUF 取帧)─▶ 帧到达，TH1 为各消费者签发 lease（引用计数 = 消费者数）
        ├─ 同步消费者（TH2b 主路径）：处理返回后立即 release
        ├─ 异步消费者（RGA / NPU）：必须等 completion fence / 回调后才 release
        └─ TH3：必须先复制触发帧，再 release
   └─(引用计数归零)─▶ TH1 才可把该 buffer_index + generation 重新 QBUF
```

硬约束（逐条来自 §5）：

1. **仅 TH1 可 `QBUF`**；消费者只持 lease。
2. **任何模块不得 `close(dmabuf_fd)`**。
3. **引用计数未归零不得重新入队**。
4. **禁止强制回收仍在使用的 lease**。
5. 超时（lease / fence / 提交）→ `E_TIMEOUT`，记 `lease_timeout` 事件（`docs/logging.md` §4 的必带字段：`lease_id` / `seq` / `buffer_index` / `generation`），随后走**受控退出**——**禁止在消费者仍访问时强制 close**（§5 启动/停止顺序）。

## 4. 唯一 stream on

- `stream_on_once()` 在**全生命周期只调用一次**（§5 契约 C、§10.5-6 强制项）；启动序 = TH4（DSI/CRTC 就绪）→ TH2 → TH1（开流）→ TH5（§5）。
- 该次调用的结果（成功/失败、节点名）按 `docs/logging.md` §4 的 `stream_on_once` 事件落日志。
- 失败处置按 §10.5 矩阵；**演示路径以"只开一次"为唯一口径**——启动序失败即 `E_V4L2` → `FAULT_EXIT`，"停流 → 等 → 再开"**仅作 M0/M1 板级调试期的诊断手段、不得进入演示路径**（v3.17 裁定 O26）。
- **不得为换预设而停流**（预设启动选定，§8.1 裁定 O10）；**亦不得因软复位停流**（v3.17 裁定 O26，见 §8）。

## 5. 取帧与时间戳

- 时间戳取 **V4L2 buffer timestamp**，**不取应用 DQBUF 时刻**（§6.5）。
- 同时读取 `V4L2_BUF_FLAG_TSTAMP_SRC_MASK`，把 `SOE` / `EOF` 写入 `FrameDesc.timestamp_source`；二者语义不可混用（§6.5）。
- 启动自检须校验时钟域为 MONOTONIC 且来源可判定（§10.5-6，**强制项**）；校验结果落日志。
- 运行期来源改变或不可判定：**仅记录 + 该窗口指标作废**——不停机、不额外重检、不触发 RSM 迁移（§6.5 裁定 O4）；本模块只负责发出 `timestamp_source_changed` 事件。
- `seq` 由本模块分配且单调递增；**下游不得重编号**，本模块自身也不得在重试/重发时复用或改写（§5）。

## 6. 四源触发与触发 FSM

- 输入源与默认开关见 §8.1；四个源**共用同一套 FSM**，状态与迁移逐条以 §5 的"触发 FSM"表为准（本文不复述状态名与迁移）。
- 实现要点：
  - 消抖窗用 `mono_ns` 计时（`trigger.debounce_ms`，取值以 §10.4 为准）；窗内后续事件**丢弃**（防连发两次 HQ）。
  - GPIO 抖动与 evdev 按键 repeat 在同一措施内处理，不得各自去抖造成重复触发。
  - `HQ_BUSY` 期间触发**一律丢弃**：`discarded_triggers` 递增 + 记 `trigger_discard`（`docs/logging.md` §4）；**不排队、不补做、无 pending 位**（§5 裁定 O18）。
  - 成功受理记 `trigger_accept`，并返回 `seq_src`；`submit_trigger()` 返回 0 表示丢弃（§5 契约 C）。
- 触发受理后**必须立即复制原始暗帧**（§5 池耗尽策略：TH3 触发帧必须立即复制）；该副本供 TH3 推理用（**v3.86 裁定 O102：原「与 §8.3 集合 A 共用」已随存图取消**）。
- 快照冻结（§8.1 裁定 O5）由本模块负责：按键时把当前帧复制到专用快照槽，TH4 此后显示该静态帧；**采集与触发链照常运行，冻结不改触发 FSM 状态**；冻结窗口从计量窗排除（§6.5）。

## 7. 池耗尽策略

按 §5 逐条实现，优先级不得调整：

1. TH2b 实时显示优先；
2. TH2a 可跳过本次估计并沿用 EMA；
3. TH3 触发帧必须立即复制；
4. 无可用缓冲时丢**最旧的"未签发 lease"帧**；
5. **禁止强制回收仍在使用的 lease**。

pool starvation 次数须可被 `bench.py` 报告取用（§5：M0/M2 压测须记录）。

## 8. 启动序 / 退出序的责任划分

| 时刻 | 本模块的动作 |
|---|---|
| 启动 | 在 TH4 就绪、TH2 就绪之后初始化并**开流一次**；随后启动 TH5 |
| 软复位（§10.6-C 短按，v3.17 裁定 O26） | ① 停止签发新 lease；② 等待在途 lease / fence **有界清空**；③ **暂停受理触发**；**到此为止**——**不 `STREAMOFF`、不释放 DMABUF 池、不释放 CRTC/plane**；期间 TH1 保持可 `QBUF`（未签发 lease 的帧照常归还）。随后配合 §10.5「软复位时的自检复核」（只校验不重建；第 6 项校验流活跃且 `stream_on_once()` 计数恒为 1，**禁止再次调用**），通过后恢复受理触发；复核失败 → `FAULT_EXIT`，**该路径才执行下方的完整退出序** |
| 退出（长按 / 退出信号 / `FAULT_EXIT`） | ① 停止签发新 lease；② 等待在途 lease / fence **有界清空**；③ `STREAMOFF`；④ 释放 DMABUF 池 |
| 退出超时 | 记 ERROR（`E_TIMEOUT`）+ 走受控退出；CRTC/plane 的释放由 TH4 负责，**本模块不触碰显示资源** |

> **不变量**：`stream_on_once()` 的调用计数在**进程全生命周期内恒为 1**（含任意次软复位）；软复位不是"重启链路"。部署侧 `systemctl restart` 属**新进程生命周期**，计数随进程重置，不受此限。

RSM 的 `SHUTDOWN` / `FAULT_EXIT` 优先于触发 FSM 的任何状态；进入这两态即停止签发新 lease（§5 两套状态机关系）。

## 9. 与其它模块的协作面

| 对端 | 传递物 / 契约 |
|---|---|
| TH2a / TH2b / TH3 | `FrameDesc`（字段与所有权见 §5 契约 B，本文不复述） |
| TH3 | 触发事件（`seq_src` + 源枚举 + ISP 指纹快照） |
| TH4 | `ControlState` 的控制/状态量（单生产者单消费者无锁队列） |
| TH4 | 快照冻结用的静态帧（§8.1 裁定 O5） |
| `isp_ctl` | 曝光/增益写入后的**回读值校验**归本模块（§10.5-2 强制项） |
| TH4 / TH5 | 本模块不介入显示；HDMI 缺席只影响 RSM（`MIPI_PREVIEW_ONLY`），**不得阻塞采集** |

## 10. 日志与错误码

- 事件名一律取 `docs/logging.md` §4 清单，**不得自造**；本模块相关事件：`stream_on_once`、`lease_timeout`、`timestamp_source_changed`、`trigger_accept` / `trigger_discard`。
- 错误码只取 §5 契约 A 节（`E_V4L2` / `E_STATE` / `E_TIMEOUT` 等），打印**符号名**。
- 带帧事件必须带 `seq_src` 或 `seq_est`；带状态事件必须带 `rsm=` 与 `fsm=`。

## 12. 明确不做（反模式清单）

1. 消费者侧 `close(dmabuf_fd)`；强制回收在用 lease。
2. 二次 `stream on`；为换预设停流重配。
3. **在软复位路径上 `STREAMOFF` 或释放 DMABUF 池 / CRTC / plane**（v3.17 裁定 O26：退出序只属进程终止路径）。
4. 用 DQBUF 时刻替代 V4L2 buffer timestamp；用 `utc_iso8601` 做时序比对（规则 `20-contracts.md` §2）。
5. 在 `HQ_BUSY` 期间排队或补做触发。
6. 因 HDMI 未接而阻塞采集或把启动判为失败（§3.5、规则 `30-board-safety.md` §2）。
7. 现场手改 config 取值（规则 `20-contracts.md` §4）。
