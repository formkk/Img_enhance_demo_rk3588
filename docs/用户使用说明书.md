# 极暗光增强实时演示系统 · 用户使用说明书

> 适用对象：现场操作人员 / 参观讲解人员
> 显示设备：开发板上的 **MIPI 触摸屏**（可同时连接HDMI显示器**两屏显示同一画面**）
> 操作方式：**手指点触 MIPI 屏下方按钮**

---

## 一、这套系统在演示什么

1. 把极暗环境里"看不清"的画面，变成"看得清"的画面，
2. 演示如何在只传很少数据的前提下，让机器也"看得到"。

它一共演示三条路（三个按钮），可以随时来回切换：

| 路 | 按钮 | 它演示什么 | 要等多久 |
|---|---|---|---|
| **实时路** | （不用点，开机就有） | 边拍边增强，画面流畅连续 | 实时 |
| **高质量增强路** | 「高质量增强」 | 单张画面用更强的算法做到最好效果 | 约 **10 秒** |
| **特征压缩检测路** | 「DCM 特征检测」 | 只传极小的数据量，机器检测目标 | 约 **30 秒** |

---

## 二、开机后的默认画面（实时路）

屏幕从上到下分成三块：

```
┌────────────────────────────────────────────┐
│  左窗：原始图像        │  右窗：ZDE++实时增强   │  ← 上：两块画面并排对比
├────────────────────────────────────────────┤
│  端延时 / 帧率        均值提升  原图 --> 增强  │  ← 中：状态数值行
│  色调映射曲线图        │  亮度直方图          │  ← 中：两张小图
├────────────────────────────────────────────┤
│  高质量增强  │  DCM 特征检测  │  退出（长按3秒）│  ← 下：三个按钮
└────────────────────────────────────────────┘
```

- **左窗**：相机拍到的原始画面（很暗）。
- **右窗**：实时增强结果。两窗**同一时刻**对比，效果一眼可见。
- 画面一直在动 = 系统正常工作。

## 三、三个按钮怎么用

### 1. 「高质量增强」—— 要最好的效果

**操作**：手指点一下按钮 → 屏幕画面**停住**，中间出现**进度条**：

```
        多帧时域平均中            ← 第 1 步：多帧平均降噪（小于 1 秒）
        已用时 0.0 秒
   ↓（自动切换）
        RetinexFormer 网络增强中   ← 第 2 步：深度网络增强（约 8~9 秒）
        已用时 3.2 秒
```

约 **10 秒**后，整屏显示**这一张**的高质量增强结果，并带文字说明（见第五节）。


### 2. 「DCM 特征检测」—— 传很少数据，机器也能看懂

**操作**：点一下 → 画面停住，出现进度条，分**三步**依次显示：

```
        多帧时域平均中            ← 与上一路相同
        RetinexFormer 网络增强中   ← 先做出一张高质量增强图
        DCM 特征编解码中          ← 把"机器要用的信息"压缩成很小的数据包
        特征域目标检测中          ← 接收端只凭这个小数据包重建信息并做检测
```

约 **30 秒**后，整屏显示**重建画面 + 检测框**（框上标着物体名称和把握程度），并带数据量说明。

### 3. 「退出（长按3秒）」—— 关机

**长按 3 秒**执行（**防误触**设计）。

### 返回常规画面（退出全屏）

上面两路进入全屏后，**点屏幕任意位置**即可回到有按钮的常规画面；
**不操作时**也会自动返回：**高质量增强**的结果约 **30 秒**后自动返回，**特征压缩检测**的结果约 **60 秒**后自动返回（信息多，留足讲解时间）。

## 四、各路用到的技术（简要）

### 实时路（ZDE++ 实时增强）
1. **逐帧估算亮度映射曲线**：根据当前画面整体明暗，算出一条"提亮曲线"——暗的地方多提亮、亮的地方少提亮，避免过曝。
2. **八次计算的曲线合成一次运算**：曲线是用 8 步近似迭代算出来的，系统把这 8 步**合并成一次完成**，因此能跟得上实时。
3. **硬件加速**：图像缩放、画布合成、曲线应用等都交给板上的专用硬件单元，CPU 只做调度。
   ⇒ 结果：**边拍边增强，画面连续流畅**。

### 高质量增强路（Retinexformer 网络增强）
按顺序做四件事：
1. **多帧时域平均**：连续取 8 帧叠加平均进行降噪，代价：运动物体可能有轻微残影。
2. **曲线预提亮 + 黑位锚定**：先把暗部整体抬起来，再把"最黑处"重新锚定到合理位置，避免整幅发灰。
3. **Retinexformer 深度网络**：用神经网络对画面重新渲染（在板上的 AI 加速单元运行），恢复亮度与细节。
4. **色彩增强**：在**保持亮度不变**的前提下把颜色加浓（提高饱和度），画面更鲜活。

### 特征压缩检测路（DCM）
1. 把**高质量增强结果**送进压缩链路。
2. **压的不是"画面"，而是"机器要用的那一层信息"**：系统取出网络中间层的特征（ 128 个通道），量化后做**熵编码**，得到一个小数据包（本机实测约 **24 KB**，随画面在 24~29 KB 之间浮动）。
3. **接收端只用这个小数据包**：重建特征 → 用于**目标检测**；同时用重建出的特征**另画一张画面给人看**（所以这张图**不是原图**，会略有模糊和块状——这正是"信息被压掉"的直接体现）。
4. **检测**：用 **Faster R-CNN**（一种通用的目标检测网络，可识别 80 类常见物体），在**重建后的特征**上检出目标，框上标注**类别名 + 把握程度**。

## 五、画面上的指标怎么看

> ⚠️ 屏上指标用于**说明处理效果与数据量**，是演示参考，**不是精度考核指标**（这类演示没有"标准答案图"可对照，所以不显示精度类指标）。

### 实时路（常规画面）

| 屏幕上 | 含义 | 怎么读 |
|---|---|---|
| **端延时** | 从"拍摄"到"显示上屏"的端到端延时 | 单位毫秒（ms），**越小越及时** |
| **帧率** | 每秒处理并显示的帧数 | 单位 fps，越大越流畅 |
| **均值提升** | 左窗与右窗的平均亮度 | 形如 `12.3 --> 108.6`，表示"原图 12.3、增强后 108.6"，可直观看到提亮幅度 |
| **色调映射曲线** | 当前正在使用的亮度映射曲线 | 横轴=输入亮度、纵轴=输出亮度；曲线越往上拱，暗部提亮越强 |
| **亮度直方图** | 画面明暗分布 | 灰 = 原始图像，绿 = 增强图像；绿色整体右移说明画面被提亮 |

### 高质量增强路（全屏）

- **左上角**：「Retinexformer 增强」——标明本画面所用的增强网络。
- **右下角黑色卡片**（数值均按"原图 → 增强"成对给出）：

| 指标 | 含义 |
|---|---|
| **亮度均值** | 画面整体亮度（0~255）。原图 → 增强，差值即提亮幅度 |
| **暗部占比** | "很暗的像素"占全画面的百分比。数值**下降**说明暗部被提亮 |
| **饱和度** | 画面颜色的浓郁程度（只统计**较亮区域**，避免暗处噪点干扰）。数值**上升**说明颜色更鲜艳 |
| **亮度直方图小图** | 与实时路同口径的明暗分布对比图（灰=原图、绿=增强） |

### 特征压缩检测路（全屏）

- **画面底部居中（黑底绿字）**：「DCM码流重建图」—— 明确提示**这张画面是由压缩后的数据包重建出来的**，不是原始图像。
- **画面上的检测框**：框上文字 = **物体类别 + 把握程度（0~1）**。把握程度低于 **0.5** 的目标不会显示（阈值设置，用于抑制误报）。
- **右下角黑色卡片**：

| 指标 | 含义 | 典型读数 |
|---|---|---|
| **原图像素** | 送进压缩链路的**原始画面**数据量 | 约 **1.48 MB** |
| **DCM码流** | 压缩后**实际需要传输**的数据量 | 约 **24 KB**（24~29 KB） |
| **压缩/节省** | 前一格 ÷ 后一格；以及节省的百分比 | 约 **53~64×**、省 **98%** 以上 |

> 这张卡片是本路演示的**核心看点**：**画面质量基本保住的同时，数据量只有原来的 1/60 左右。**

## 六、注意事项与常见问题

| 现象 | 说明 |
|---|---|
| 点按钮后**画面停住不动** | **正常**。这是设计如此：等待期间画面冻结并显示进度条，避免观众误以为还在实时处理 |
| 进度条第 1 步的「已用时」一直是 0.0 秒 | 正常。第 1 步（多帧平均）期间画面被占用，计时刷新暂停；进入第 2 步后会正常计时 |
| 全屏画面里的图像**略有模糊/块状** | 正常，且**正是要展示的现象**——那是"数据被压缩后重建"的代价 |
| 检测框偶尔出现**不合理的物体名称** | 已知局限：暗光 + 压缩条件下，检测模型可能误判。当前已屏蔽两类明显不合理的类别并提高阈值，若仍出现属正常现象，**讲解时如实说明即可** |
| HDMI 显示器与 MIPI 屏画面**不一致** | 不应出现。若出现请检查 HDMI 线缆后重启 |
| **别的东西都调不动** | 现场**只允许微调曝光 / 增益**；其余参数在启动前选定，需**改配置后重启**才生效（防止误操作影响演示） |
