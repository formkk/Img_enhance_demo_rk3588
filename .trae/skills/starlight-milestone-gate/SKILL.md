# 里程碑出口闸门清单

为 M0~M4 任一阶段生成出口自检清单。**只做判定与取证，不改代码、不改文档、不下技术裁定。**

## 判定依据（唯一权威，逐条只写节号）

| 闸门 | 依据 |
|---|---|
| 指标与复现 | 主基准 §11 该阶段出口标准、§13 对应行的复现方式 |
| 回归 | §11.2 该阶段行的回归项（**全过方可出口**） |
| 配置 | §10.4 键表中"定稿时点 ≤ 本阶段"的键**零空缺**；三态规则（含 `provisional`）见 §10.4 |
| 登记 | `docs/measurements.md` 中"阻塞里程碑 = 本阶段"的行**三列完整**（结论值 · 依据报告路径 · 复检时点） |
| 文档回写 | `.trae/rules/00-ssot.md` §4 的变更回写义务表 |
| 执行纪律 | `.trae/rules/40-gate.md` §1~§5 |

## 步骤

1. 确定阶段号 `k`（M0~M4）。读主基准 §11 该行、§11.2 该行、§13 全表、§10.4 键表、`docs/measurements.md`、`docs/plans/M<k>.md`（若存在）。
2. 逐条列出 §11.1（仅 M0）/ §11 出口标准项，判定状态。
3. 逐条列出 §11.2 该阶段回归项，判定状态。
4. **config 键完整性**：筛出 §10.4 中定稿时点 ≤ 本阶段的每一键，核对 `config.yaml`：存在且非空 = 过；空值 = 未定稿；键缺失 = 未定稿。表外键另外单列（违规）。
5. **登记完整性**：对 `docs/measurements.md` 中阻塞本阶段的行，检查三列是否已回填；出现 `provisional` 即判违规（实测项禁用，见 §15 收口规约）。
6. 输出闸门清单（见下方模板），并在末尾给出总判定：**可出口 / 未过（列出阻断项）**。

## 输出模板

| 闸门项 | 状态（过 / 未过 / 缺证据） | 证据路径（报告文件或配置键） | 责任人 |
|---|---|---|---|
| §11.1-<n> / §11 标准 | | | 实现者自测 |
| §11.2-<n> | | | 实现者自测 |
| §10.4 键完整性 | | `config.yaml` 逐键 | 实现者自测 |
| `docs/measurements.md` 登记 | | 报告路径 | 实现者自测 / 验收人复核 |
| 回写义务（`00-ssot.md` §4） | | 主基准 §10.4 / §14 / §15 | 实现者 |

## 硬规则（违反即判违规）

- **未过项不得以文字说明代替证据路径**（§13：截图、口述、单次体验不可替代可复现命令）。
- **闸门未过不得开始下一里程碑的实现**，只允许"解除阻塞"动作（补测、补报告、走 §15 裁定）。
- **不得默认放宽验收上限**；需要放宽必须走 §15 裁定并回写 §13。
- **禁止引用历史数字**作为依据或换算基础（39.69 dB / Retinformer 7.1 s / 3562 ZDE++ 255 ms 均不可用）。
- 报告与回归记录须存放在 `storage.dir` **之外**的工程目录。
- 引用一律写 `§x.y` / `O<n>` / `docs/<file>.md §<n>`，禁止"上文所述"式无锚点引用。
