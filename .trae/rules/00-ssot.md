# 规则 00：SSOT 与文档架构

> 本规则只写**纪律与闸门**，不复述任何规范取值。所有取值一律以所引节号为准。

## 1. 权威顺序（冲突以此裁决）

1. **主基准** `RK3588极暗光增强实时演示系统_项目基准_v3.31.md` —— 唯一基准，承载**裁定与契约**
2. **从属规范** `docs/build.md` / `docs/logging.md` / `docs/measurements.md` —— 承载**规格取值**；与主基准冲突时以主基准为准
3. **设计文档** `docs/design/*.md` —— 承载**实现选择**；冲突时以第 1、2 层为准
4. 代码与 `config.yaml`

## 2. 三层文档架构（切分维度：按契约面，不按阶段）

| 层 | 位置 | 回答什么 | 效力 | 备注 |
|---|---|---|---|---|
| A 规格类 | `docs/{build,logging,measurements}.md` | 必须是什么 | 从属规范，冲突以主基准为准 | 主基准**不重复定义**其取值，只引用路径与版本 |
| B 设计类 | `docs/design/<模块>.md` | 打算怎么做 | 不得引入新取值、不得裁定未决项 | **按模块切，正交于阶段**（阶段由 §11 承担） |
| C 记录类 | `docs/plans/M<k>.md`、`docs/evidence/*.md` | 实际做了什么、得到什么 | 非验收依据 | `plans` 按阶段（薄：勾选 + 证据链接）；`evidence` 按一次实验 / 一个 O 项 |

**禁止按阶段建"设计"文档**：同一模块会被多个阶段文档重复描述，即构成多 SSOT。

## 3. 子文档五条硬约束

1. **不复制取值**：只写"见 §X"或"与 §X 的差异"；凡复制规范取值即判 SSOT 违规。
2. **不裁定未决项**：遇到 §15 登记中的开放项，必须先在 §15 裁定并回写正文，禁止在子文档内塞入取值后继续推进。
3. **头部四件套**：地位 / 效力 / 对应主基准节 / 状态（`draft` | `frozen` | `[待复核]`）——照 A 层三份文档的头表格式。
4. **登记义务**：新建、改名或删除子文档，必须同步回写主基准 §10.3 代码结构树与 §14 变更记录，否则视为孤儿文档。
5. **不进验收链**：子文档不得作为达标依据；验收只认 §13 的复现方式 + §11.2 的回归项 + `bench.py` 报告。

## 4. 变更回写义务（改动即触发）

| 改动类型 | 必须回写 |
|---|---|
| 任何技术裁定 | 对应正文节 + §10.4 键表（若涉及键）+ §14 变更记录 + §15 状态 |
| 涉及从属规范 | 该附件规范 + 主基准 §14（效力条款：变更须同步） |
| 实测数据产出 | `docs/measurements.md` 对应登记表三列 + 主基准 §14（若构成裁定） |
| 代码实现偏离契约 | 先裁定再改代码；禁止"代码先行、文档后补" |
| 只改登记表 / 只改代码 | **不允许** |

## 5. 术语与编号

- 开放项编号 `O<n>`、风险编号 `R<n>`、里程碑 `M<k>`、M0 子项 `M0-<n>` 均为**既有编号空间**：只许追加，不得改写旧编号含义，也不得复用已关闭编号。
- 引用一律写成 `§x.y` / `O<n>` / `docs/<file>.md §<n>`，禁止"上文所述""之前提到"这类无锚点引用。
