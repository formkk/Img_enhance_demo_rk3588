# 规则 30：板上安全与性能红线

> 依据散布于 §3.3、§5、§6、§7、§10.5；本规则只列红线，不复制预算数值。

## 1. 采集与内存所有权（破坏性最高，先看这条）

- **全生命周期只 `stream on` 一次**；启动序与退出序以 §5 为准，不得自行调整顺序。
- DMABUF：仅 TH1 可 `QBUF`；消费者只持 lease，**不得 `close(dmabuf_fd)`**；引用计数未归零不得重新入队。
- 无可用缓冲时丢最旧的**未签发 lease** 帧；**禁止强制回收仍在使用的 lease**。

## 2. 显示

- 主路径是 **DRM 双 CRTC**；`/dev/fb0` 不作主路径；connector 由运行时解析，**禁止写死 crtc id**。
- 关桌面两态按 §2.3 区分，禁止把开发态切换写成默认态。
- HDMI 缺席是可降级项：不得因 HDMI 未接而阻塞主链路或把启动判为失败。

## 3. 性能红线（非优化项）

- **8 次迭代必须单遍融合**；未融合即判未达标，不得以"编译器会自动优化"免检。
- **禁止 CPU 全帧混合**做淡入淡出。
- RGA 是共享设备：调用前确认多核启用状态与本轮排队计入方式（§6.1、§10.4）。
- 超标归因必须先扣空链路基线；基线缺失时先补测，**不得直接改实现**。

## 4. 板上操作权限

- 默认只做**只读探测**（节点枚举、参数回读、日志读取、容量查询）。
- 具有副作用的操作——停流 / 复位 / 注入故障 / 填满分区 / 修改 systemd 单元——必须先说明影响面与**恢复步骤**，并取得确认后执行。
- 故障注入类实验（`docs/measurements.md` §4）必须一步一恢复，禁止连续注入后一次性收拾。

## 5. 目录纪律

- 日志目录与存图目录分离，且互不受对方的轮转 / 淘汰策略影响。
- 日志写失败不得阻塞主链路（降级口径见 `docs/logging.md` §2）。
