# 规则 10：证据纪律

> 取值与判据以主基准 §6.5、§13、`docs/measurements.md` 为准；本规则只写"什么时候不许下结论"。

## 1. 结论的三要素（缺一即不得表述为结论）

1. **依据报告**：`bench.py` JSON 报告的**文件路径**（字段清单见 §6.5，本规则不重定义字段）。
2. **测量条件随行**：板型 / 权重哈希 / 曲线档 / 精度档 / config 快照哈希——缺任一项视为未登记。
3. **时钟口径**：时序比对只用 `mono_ns`（`CLOCK_MONOTONIC`）；时间戳来源（SOE / EOF）须随行注明。

## 2. 禁止项（触发即判违规，不得"先写着日后再改"）

- 引用任何历史数字作为依据或换算基础——**历史数据已撤销或仅留档**（见附录 A/C、§6 声明）。
- 跨模型、跨 shape、跨平台线性外推（ZDE++ 与 HQ 各只用同模型实测）。
- 用历史总 FPS 反推函数级耗时。
- 延迟按时间就近配对——必须**按 `seq` 回填**。
- 静默丢弃后只报分位数——配对率与丢弃帧数必须随报告给出。
- 在 §13 / `docs/measurements.md` / 验收报告中用截图、口述或单次体验替代可复现命令。
- **对链路输出（PNG / RGB / JSON）做非必要的人为后处理（如 γ 提亮、对比度增强、直方图均衡）后，作为"审查图"或量化依据**——**链路输出必须原样归档、原样量化**；一切非线性后处理副本一律**不得生成**（**v3.83 裁定**：`_view` 后缀 γ 目视副本被判定"多此一举、均值超人眼舒适范围、放大噪声"，**该项已废弃，日后不许再做**）。确需看清暗画内容的正确做法，是**修好 O54（显式 CSC/range）让链路输出本身正确**，而非后处理。

## 3. `provisional` 白名单

`provisional` 仅适用于 §10.4 明列的代用数据项（M0 阶段、M1 复检）。**其余任何位置不得使用 `provisional` 占位**；实测/登记类四项尤禁（见 `docs/measurements.md` 头部效力条款）。

## 4. 证据归档

- 报告与回归记录存放在 `storage.dir` **之外**的工程目录，不得被 §8.3 的环形淘汰覆盖。
- 权重、模型、IQ 文件变更后：按 O11 的复检规则处理（全量重跑清单以该裁定为准），并同步复检 `docs/measurements.md` 对应行的"复检时点"。
