## 0. 一句话

原设计让 **HQ 独占 HDMI**，为此背上了 §3.5 的四态时序（未触发 / 处理中角标 / 300 ms 淡入 / 未接弹层）与"演示要接 HDMI"的观感。现改为：**两屏同画面（唯一 1920×1080 合成画布）+ 点击增强窗查看 HQ 单张结果全屏**。§3.5 整表可删，代价是**新增全屏视图、新增指针输入、改画布坐标域与 DRM 槽语义，并改写 G2/G4/G5 与 §13 四行**。

## 1. 变更定义

### 1.1 前后对照

| | 原设计 | 现设计 |
|---|---|---|
| MIPI | 实时双窗 + OSD 指标区 + 按钮区 | **不变**（画布仍 1024×600，**1:1 零改动**） |
| HDMI | **HQ 独占**：未触发保持上一张 / 处理中角标 / 300 ms 淡入替换 / 未接则 MIPI 弹层 2.5 s | **RGA 每帧把 MIPI 画布整幅放大 1.875×，写进自己的 1920×1080 画布**（双画布镜像） |
| 画布结构 | 两槽各自画布（1024×600 / 1920×1080） | **结构不变**——改动只是 HDMI 画布的**内容**由"HQ 独占"变为"镜像" |
| 看 HQ 大图 | 自动（HQ 完成即替换 HDMI） | **点击增强窗** → 触发 HQ → 完成后**全屏显示该单张结果** |
| 全屏内容 | — | **HQ 单张结果**：HDMI = 1920×1080（RGA 放大 2.0×，1:1 显示）；**MIPI = 960×540 原生 1:1 居中**（黑边由画布清黑产生） |
| 全屏退出 | — | **点击内容区任意处**；兜底 = **30 s 超时自动退出** |
| 单屏使用 | MIPI 单显天然支持；HDMI 单显被 §10.5-4 排除 | **MIPI / HDMI 均可单显**；HDMI 单显由**鼠标**操作 |

### 1.2 显示视图定义（取代原 §3.5 的四态表）

| 视图 | 内容 | 进入 | 退出 |
|---|---|---|---|
| **常规视图** | ZDE++ 实时双窗 + OSD 指标区 + 3 键按钮区 | 启动即此；全屏退出后回此 | — |
| **全屏 HQ 视图** | HQ 单张结果（1920×1080；DSI 侧缩到 1024×600 + 上下 12 px 黑边），**隐藏 OSD 与按钮区** | **HQ 完成时**（由指针点击触发的那次，见 D6） | 点击内容区任意处；或 30 s 兜底超时 |

**处理中提示**：复用 **§8.2 的 OSD 次行**（"高质量增强处理中… / 完成"），在**常规视图期间**显示——不新造提示机制。

### 1.3 交互时序

1. 常规视图：ZDE++ 实时链路运行。
2. **点击增强窗**（或**点击底栏「触发HQ」按钮**，两者完全等价）→ 取**点击那一刻的原始暗帧**（与 §5-B 触发契约一致）→ 走 HQ（`hq.active_shape = 960x544`，实测 **10014 ms**）。
3. 等待期（≈10 s）：**常规画面继续实时刷新** + OSD 次行提示"处理中"。
4. HQ 完成 → **进入全屏 HQ 视图**（两屏同时）。
5. 全屏内点击任意处 → 回常规视图；或 30 s 到 → 自动回常规视图。
6. **唯一触发源 = 指针点击**；该次 HQ 完成即进入全屏（全屏期间不存在其它触发源，点击在全屏态即退出，故不存在"全屏中途被新结果替换"的情形）。

## 3. 影响面

### 3.1 架构与状态机

- §3.3 链路图末段、**§3.5 整表改写为"显示视图定义"**、§5 TH5 段（职责退化为"热插拔 + 状态"）、§5 数据契约的"HQ 结果槽（TH3 → TH5）"行。
- **RSM 受影响**：`MIPI_PREVIEW_ONLY` 的行为定义（"HDMI 不在 ⇒ HQ 走 MIPI 弹层"）**对象消失** ⇒ 该状态行为变空，只剩迁移。§5-A 表、§10.5-4/-5、§11.2 M2-1 ① 须改写。
- **状态机纪律（须遵守）**：O3 已裁定全链**只两套状态机**（RSM + 触发 FSM），"显示不另立状态机、沿用 §3.5 的行为定义"。新的"常规 / 全屏"**不另立第三套**，而是照同一先例写成**显示视图定义**（§1.2）。

### 3.2 契约面

| 项 | 变更 |
|---|---|
| §5-B `ControlState` | 需增**光标位置**与**显示视图**（先例 = O56 增 `seq` / `t_capture_ns` 两个只读副本字段，签名不变） |
| §5-C `display_hdmi.publish()` | 语义（"把 HQ 推给 HDMI"）消失 ⇒ 须裁定后回写；TH4 变"合成 + **双槽**翻页" |
| §5-C 既有签名 | **逐字不动**；新能力一律走**追加** `*_slot` 风格函数（先例 = O70） |

### 3.3 里程碑与已出口证据

| M2-1 已出口项 | 变更后 |
|---|---|
| ② 双屏通路（modetest 双 CRTC 色条） | **有效** |
| ③ `display.hdmi_mode_selection=edid_prefer_1080p` | **有效**，且**更关键**（画布原生 1920×1080） |
| ④ 双屏满载画布流量（398.3 MB/s / `dmc/load` 增量 ≈4 个百分点） | **有效**，口径与镜像后更接近（仍为上限口径） |
| ① RSM 往返（注入式 ×3 双向 + 3600 帧整链） | **"过"仍成立**（迁移可达），判据语义须随 RSM 泛化重写 |

- **O67 / O68 → 建议标"取消"**（对象消失，非推迟）。
- §13 四行须重写：「HQ 展示」「OSD」「交互」**+「实时画质」（含"512×288"字样）**。

### 3.4 性能

- §5 TH4 段"**HDMI 仅 HQ 完成时 1 次 blit**"**被推翻**。
- **镜像本身不新增扫描带宽**（HDMI CRTC 只要 enable 就在扫；v3.83 已按双屏扫描折算 ≈645 MB/s）；常规态净增 = **多一次 pageflip**。
- **合成画布放大**：1.84 MB/帧 → **6.22 MB/帧**（+4.4 MB/帧；按现基线 `fps 22.3` 计 ≈ **+97 MB/s**）。
- **内存反而省**：今天 slot0 2×1.84 + slot1 2×6.22 = **16.1 MB** → 共享后（三缓冲）3×6.22 = **18.7 MB**（**净增 ≈2.6 MB**；若与今天同为双缓冲则省 ≈3.7 MB）。
- 任何"压了 fps / 延迟"的判定**必须先扣空链路基线**（规则 `30-board-safety.md` §3），而 `metrics.idle_link_baseline` 至今缺失（**O76**）⇒ 归因闭环前不得据实测改实现。

## 5. 可行性

### 5.1 路径取舍（**2026-09-20 修订为 C-RGA**）

> **修订**：用户后续选定 **C-RGA：双画布 + RGA 放大镜像**（§4 D19/D20），**取代** C2 / C2-乙。下表保留为取舍记录。

| 路径 | 结论 |
|---|---|
| C1（画布 = 1024×600） | 当时否——理由"全屏 HQ 会被缩到 600p 再放大"；**C-RGA 证明该理由不成立**（HQ 态 MIPI 走原生 1:1、HDMI 走 D，双画布各自 1:1） |
| C2（画布 = 1920×1080） | ~~采纳~~ **作废**（会连带 §3.4 重排、plane 缩放、三缓冲） |
| C2-乙（窗内容 512×288 + RGA 放大进画布） | ~~采纳~~ **作废**（重采样往返 + plane 缩小） |
| **C-RGA（双画布 + RGA 放大镜像）** | **采纳**（D19）——两槽 buffer 独立（今天的结构），**全程 1:1、无 plane 缩放** |

- **C-RGA 的收益**：§3.4 布局零改动、曲线应用 / OSD 统计 / `WIN_W/WIN_H` 零改动、**无 plane 缩放依赖**、**无三缓冲**、DSI 侧常规态**零重采样零黑边**、HQ 态 MIPI **零重采样**（q1）。
- **C-RGA 的唯一新增成本**：常规态**每帧一次 RGA 放大 blit**（1024×600 → 1920×1080），**P0b 实测中位 2.009 ms**（p90 2.166）——见 §11 与 §13-1。

### 5.2 `drm_core` 现状与缺口（**已代码勘察**）

| 事实 | 位置 |
|---|---|
| 每槽**自建画布与 fb** ⇒ 槽间**不共享 buffer** | `native/drm_core.c:158-192` |
| 初次 modeset 走 **`drmModeSetCrtc`**，之后 **`drmModePageFlip`**；**全文无 `drmModeSetPlane`** | `:197` / `:236` |
| pitch / fb 尺寸全部取自 `cfg.canvas_w/canvas_h`（与 connector mode 解耦） | `:163-165` |
| 槽化已就位：`g.slot[2]`、`user_data=(seq<<2)|slot`、`*_slot` 系列均为追加 | `:56-104`、`:226-320` |
| `drm_is_configured()` 判的是**槽 0（DSI）**；`drmSetMaster` 在 `open_connector` 内 | `:104`、`:118-141` |

⇒ 需新增四类能力，**全部走追加**：① **镜像槽**（槽 1 复用槽 0 的 fb）；② **显式 plane 几何**（src + dst rect，含黑边）；③ **槽 0 归属可配置 + 首配置者取 master**（D13）；④ **`nbuf=3`** 的承载与翻页索引。

### 5.3 三缓冲的必要性（D14）

两 CRTC 的 vblank 相位独立。双缓冲共享后，TH4 翻完槽 0 就去写下一块时，槽 1 可能仍在扫那块 ⇒ **HDMI 撕裂**。三缓冲下任一时刻至多两块被扫、一块在写 ⇒ 只需保证**任一槽不落后 ≥2 块**；**不增加每帧等待**（对比"两槽同帧同步翻页"要多等最多一个刷新周期 = 16.7 ms，直接吃帧预算与延迟）。

### 5.4 HDMI 单显与槽语义（D13）

- 现状断点三处：§10.5-4 把"DSI 绑定 + 取 master"列为**强制项**；`display_hdmi.init_canvas()` 前置 `if not _n.drm.is_configured(): return 0`；启动序"**TH4（DSI/CRTC 就绪）→ … → TH5**"。
- D13 落地后：三点全部改为"**至少一个显示口就绪**"，并须重定义"**不带 `_slot` 的别名归哪一槽**"（现语义 = 一律槽 0/DSI）。

### 5.5 带宽与内存（用既有实测直接计）

见 §3.4。**不再外推**；DSI 侧 plane 缩放的读量级与三缓冲的实际影响，均须板上 `dmc/load` 实测（口径沿用 M2-1 ④：**只报增量、不做带宽反推**）。

|---|---|---|---|---|
| **512×288**（基线复现） | **3.994 ms** | 3.991 / 3.999 / 4.008 | mismatch 0 / max_abs 0 | 26.5 MB/s |

**目的**：量测 C-RGA 的**唯一新增成本项**——常规态每帧一次"整幅画布放大镜像"。

**条件随行**：板上（`board`，桌面态、安静）；dma-buf（**`fd` 模式**，与交付链路的画布一致）+ **`core_mask=3`**（§10.4 定稿值）+ `IM_SYNC` 同步提交；计时前 **1 次预热**（不计入）以取稳态；`runs=30`；探针源码 = `docs/evidence/reports/display-arch-change/rga_mirror_probe.c`（本轮新写，随报告归档；同一 `improcess` 口径）。

## 13. 未验 / 未知（如实登记，不得写成结论）

1. **每帧镜像对 fps 的实际影响**——P0b 实测镜像 blit **中位 2.009 ms/帧**（p90 2.166）⇒ 按现基线 44.84 ms/帧 **测算 ≈21.3 fps**，**相对 O75 的 ≥21 仅剩 1.6% 余量** ⇒ **集成后必须实测**；若跌破，退路 = 低频镜像（当前选每帧）。**注：VOP2 plane 缩放能力已不再是硬前置**（C-RGA 全程 1:1）。
2. **放大 / 缩小的实际画质**（DSI 侧重采样往返、HDMI 常规态）——**未验**。
3. **光标每帧画进画布的实测开销**——理论上与 `osd_core` 小矩形同级（≪ `canvas_ms` 中位 1.43 ms），**未实测**。
4. **移除 GPIO / UART / TIMER 后的两个代价**——① 触控（或鼠标）失效时，退路只剩 **30 s 全屏兜底 + 串口调试台**（GPIO 备用键已不存在）；② **脚本化测试入口 `TRIG` 消失**，§11.2 M2 ① 的状态机测试失去"脚本注入"手段（只能靠指针点击），自动化程度下降。**两项均未评估**。
5. **TIMER 在旧取值下实际无效**（周期 8 s < 实测推理 **10014 ms** ⇒ 每次被 `HQ_BUSY` 丢弃）——**事实**，是本轮移除的依据，须随 O84 留档。
6. **§6.3 画布内存口径分歧**（3 B/px vs 4 B/px，既有）。
7. **三缓冲下"任一槽不落后 ≥2 块"的不变式**在真实链路（含 10 s 的 HQ 在途、软复位）中是否始终成立——**未验**。
